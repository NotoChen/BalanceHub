# 签到浏览器执行器

Rust 保留 NewAPI 认证、验证分类、提交及回读判断；此进程仅执行同源浏览器操作。
账号凭据使用私有 stdin/stdout JSONL 通道，不进入命令参数、日志或前端进度事件。

App 使用独立 Chrome/Edge Profile。先自动等待和有限点击验证组件，必要时显示人工验证提示；
完成后继续提交并读取站点的今日签到状态。关闭验证浏览器、取消和超时都会终止当前尝试。
读取状态时的连接失败或非 JSON 响应也可由浏览器重新读取；429 和普通认证错误
不触发浏览器。标准 NewAPI 签到先确认今日尚未签到；POST 失联只回读，不盲目重发。

主安装包不携带 Node 或浏览器。设置 → 自动化 → 浏览器辅助签到中确认安装后，
组件从官方来源下载到 App 数据目录；每个可执行归档均检查固定 SHA-256。
可使用本机 Chrome/Edge/Chromium/Brave，也可选择安装独立 Chromium；已安装独立浏览器时优先使用它。
检测在 App 启动、打开组件面板和安装完成时进行，普通检测缓存 5 分钟；每次浏览器签到前
强制检查文件。组件版本与 App 绑定，版本不匹配时提示确认更新，不后台下载。
macOS、Windows 和 Linux 的 x64/ARM64 均有固定下载清单；Windows ARM64 使用 Chromium x64，
需要系统的 x64 兼容支持。Linux 需要图形桌面和 Chromium 系统依赖，不自动提权安装系统包。

单站、批量和定时签到共用 Rust 任务状态。批量/定时遇到人工验证会释放浏览器，
在任务中心和卡片显示“继续验证”。手动验证可保留窗口，完成后自动继续。
未安装组件显示待安装；关闭 App 会结束进程内任务，账号配置和已保存记录保留。
定时调度每 30 秒检查到期任务，普通失败按 30 分钟退避、每日最多 3 次；
等待人工处理、取消和结果未确认不会自动反复提交。

AgentRouter 按站点域名识别登录签到，强制账号密码重新登录并回读同一账号状态；
Cookie 和访问令牌不能替代该站点的每日登录。站点自定义 action/cData、OAuth 登录尚未实现。

源码开发使用隔离应用标识和配置，执行 npm run tauri dev；不要启动或修改本机安装版。

2026-09-16 实测：在隔离的真实 Tauri 开发 App 中，用已授权账号测试 7 个真实站点。
其中 4 个自动完成 Turnstile 验证、签到提交、站点回读确认和本地记录保存，每个约 8–18 秒，
无需人工介入；另 1 个通过普通接口签到成功。这 5 个均为新增签到，各新增 1 条本地记录。
其余 2 个分别返回 HTTP 502 和无效签到状态，均在提交前停止，未计为成功。
当前仅实测 macOS，其他平台打包待验证；站点策略变化后仍可能需要人工验证。

可选组件也已在 macOS 的隔离开发 App 中实际下载、校验并安装独立 Chromium；
关闭安装弹窗后后台进度继续，安装完成后使用下载的 Node 和 Chromium 通过同源请求冒烟检查。
新增及既有检查共通过 88 项前端测试、385 项 Rust 测试、strict Clippy 和平台脚本检查。
AgentRouter 登录签到仍需用户使用自己的账号验收，自动检查不代替用户验收。
