# 签到浏览器执行器

Rust 保留 NewAPI 认证、验证分类、提交及回读判断；此进程仅执行同源浏览器操作。
账号凭据使用私有 stdin/stdout JSONL 通道，不进入命令参数、日志或前端进度事件。

App 使用独立 Chrome/Edge Profile，等待验证码服务自行完成非交互验证，不模拟点击验证码。
Turnstile 要求人工操作时立即提示；手动任务保留窗口，批量和定时任务让出窗口，等待用户继续。
验证完成后继续提交并读取站点的今日签到状态。关闭验证浏览器、取消和超时都会终止当前尝试。
组件加载失败、验证错误、令牌过期和不支持的浏览器均返回明确原因，不再静默等到总超时。
验证使用独立小窗，不显示浏览器标签栏和地址栏；Turnstile 页面只保留验证框和简短提示，
按内容调整窗口大小，验证内容展开时自动增高。整页 Cloudflare 验证保留站点原始内容，
可滚动或手动调整窗口大小。
验证窗口标题以中转站名称开头；未命名时显示域名。Turnstile 小窗同时展示名称和域名，
页面导航或站点修改标题后仍保留站点标识，Cloudflare 检测继续读取站点原始标题。
普通签到请求最多 6 个并发，浏览器验证全局串行排队，一次只显示一个验证窗口；
各站点使用独立账号会话。进度弹窗按站点显示“排队等待验证窗口”。
读取状态时的连接失败或非 JSON 响应也可由浏览器重新读取；429 和普通认证错误
不触发浏览器。标准 NewAPI 签到先确认今日尚未签到；POST 失联只回读，不盲目重发。

主安装包不携带 Node 或浏览器。设置 → 自动化 → 浏览器辅助签到中确认安装后，
组件从官方来源下载到 App 数据目录；每个可执行归档均检查固定 SHA-256。
面板列出检测到的 Chromium 系浏览器，也支持手动选择可执行文件或 macOS 应用，以及安装独立 Chromium。
本机模式只下载 Node.js 和 Playwright 辅助组件，复用已有浏览器程序；独立模式额外下载 Chromium。
下载前显示所需内容与预计体积，进度百分比最多两位小数。切换已有浏览器无需重新下载辅助组件。
普通环境检测缓存 5 分钟，可手动重新检测。Windows 检查 HKCU/HKLM 的 32/64 位注册表视图
（App Paths、StartMenuInternet）及常见安装目录；macOS 检查系统和用户应用目录，手选应用读取
CFBundleExecutable；Linux 检查 PATH 与常见目录。浏览器路径按实际文件去重。
安装或切换先在临时空白环境验证浏览器能否启动，成功后才保存选择；失败或取消保留原有组件。
浏览器、Node 或 Playwright 文件变化会使已保存的验证失效，使用前重新验证。
组件版本与 App 绑定，版本不匹配时提示确认更新，不后台下载；下载独立浏览器时复用版本一致的辅助组件。
macOS、Windows 和 Linux 的 x64/ARM64 均有固定下载清单；Windows ARM64 使用 Chromium x64，
需要系统的 x64 兼容支持。Linux 需要图形桌面和 Chromium 系统依赖，不自动提权安装系统包。

单站、批量和定时签到共用 Rust 任务状态。批量/定时遇到人工验证会释放浏览器，
在任务中心和卡片显示“继续验证”。手动验证可保留窗口，完成后自动继续。
未安装组件显示待安装；关闭 App 会结束进程内任务，账号配置和已保存记录保留。
定时调度每 30 秒检查到期任务，普通失败按 30 分钟退避、每日最多 3 次；
等待人工处理、取消和结果未确认不会自动反复提交。

中转站编辑中的“签到与验证”提供三项独立设置：

- 签到方式：自动选择、标准签到、会话签到、重新登录签到。手动选择优先于站点预设；
  自动模式下 AnyRouter 使用会话签到，AgentRouter 使用重新登录，其余 NewAPI 使用标准签到。
  同类站点可直接选择相应方式，不需要按域名增加适配器。
- 允许浏览器辅助处理站点防护：默认开启。关闭后不注入或复用盾 Cookie，不自动求解或打开页面验证；
  浏览器启动使用本地生成的内容页，避免配置和 Cookie 就绪前访问站点。
- Turnstile 签到验证：自动检测，或每次提交前验证。它独立于站点防护开关，使用当次新鲜令牌。

HTTP 与浏览器复用同一套签到业务步骤。登录阶段遇到验证时保留登录步骤，
不能把缓存的旧会话当作重新登录成功。重新登录签到只确认登录和同一账号状态，
奖励是否到账以站点记录为准。账号密码通过登录接口执行；通过“登录并导入”绑定的账号，
复用该账号的独立浏览器环境重新登录。仅有手工 Cookie / 访问令牌、未绑定登录账号时不能重新登录。
浏览器先清除目标站点的旧会话，再尝试选中绑定平台的登录按钮；授权确认、账号选择和验证码由用户处理。
必须观察到本次登录响应，并回读确认原站点用户，刷新令牌和旧页面登录状态都不能作为签到成功依据。
批量与定时的第三方重新登录先显示“继续登录”，由用户继续时打开窗口，不占用普通网络请求队列。
登录超时、账号不一致、账号绑定或配置变更均不会覆盖卡片；请求可能已提交时停止自动重试。
站点自定义 action/cData 尚未实现。

源码开发使用隔离应用标识和配置，执行 npm run tauri dev；不要启动或修改本机安装版。

## 验证边界与历史记录

Cloudflare 官方明确不支持 Playwright 等自动化浏览器。取消模拟点击可以消除 App 对人工验证的干扰，
但不能保证所有生产站点接受此浏览器环境；持续失败需要在站点原页面完成操作。
Windows 的原生探测、启动、安装和人工验证仍需在 Windows 实机上验收。
以下为历史版本的实测记录，不代表当前版本已重新通过真实站点的挑战。

2026-09-16 实测：在隔离的真实 Tauri 开发 App 中，用已授权账号测试 7 个真实站点。
其中 4 个自动完成 Turnstile 验证、签到提交、站点回读确认和本地记录保存，每个约 8–18 秒，
无需人工介入；另 1 个通过普通接口签到成功。这 5 个均为新增签到，各新增 1 条本地记录。
其余 2 个分别返回 HTTP 502 和无效签到状态，均在提交前停止，未计为成功。
真实签到交互目前仅在 macOS 实测，其他平台以发布流水线检查和构建结果为准；站点策略变化后仍可能需要人工验证。

可选组件也已在 macOS 的隔离开发 App 中实际下载、校验并安装独立 Chromium；
关闭安装弹窗后后台进度继续，安装完成后使用下载的 Node 和 Chromium 通过同源请求冒烟检查。
初版集成曾通过 88 项前端测试、385 项 Rust 测试、strict Clippy 和平台脚本检查。
AgentRouter 登录签到仍需用户使用自己的账号验收，自动检查不代替用户验收。
