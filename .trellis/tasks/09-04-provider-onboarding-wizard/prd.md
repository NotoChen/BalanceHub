# 中转站接入向导

## Goal

用一个透明、可回退的流程完成中转站接入，并在保存前明确协议、认证、检查结果和最终卡片/Key 影响。

## Requirements

- 流程顺序为地址规范化、协议探测、认证方式、凭据补全、连接/能力检查、重复计划、最终确认与保存。
- Rust `plan_provider_save` 只读返回规范化结果、认证要求、重复类型、可执行选项和预计写入动作。
- 探测模糊或失败时允许用户显式选择已注册协议；AnyRouter 仍作为 NewAPI 方言，不作为独立 UI 类型。
- NewAPI/Sub2API 默认账号密码并按 Rust 能力显示其他认证；通用 API 只显示 API Key。
- 草稿仅在前端短期存在，最终确认后才调用现有 Provider 事务；取消不得留下半成品。
- 刷新凭据、创建远程 Key 等可能有副作用的步骤必须单独说明和确认。
- 新向导替换现有新增 Provider 流程，不能并存第二套协议探测、重复判断或保存算法。

## Acceptance Criteria

- [ ] 保存前可完整看到新建、合并 Key、独立新增或覆盖的准确影响。
- [ ] 新建、合并、独立新增、覆盖、无效认证、不可达和协议模糊 fixture 均由 Rust 规则驱动。
- [ ] 任意阶段取消均不写 Provider；远端副作用只可能来自用户单独确认的步骤。
- [ ] 切换协议只在确认后清理已声明不兼容的认证字段，旧异步结果不能修改重开的向导。
- [ ] 原新增入口被替换且无废弃 composable、分支或重复协议枚举残留。

## Out of Scope

- OAuth/WebView 自动化、验证码或通用过盾。
- 静默创建远程 Key、自动选择 Agent 默认配置。

## Dependency

- Rust save planner 可先设计；向导 UI 等诊断结果契约稳定后实施并复用其结果展示语义。

## Rollback Boundary

- save planner 先以只读合同独立交付；新向导必须在完整替换新增入口且通过回归后，才能删除旧新增编排。
- 发布切换点前可回退到原新增流程；切换点后回退必须恢复一个且仅一个可用入口，不保留两套协议探测、重复判断或保存逻辑。
