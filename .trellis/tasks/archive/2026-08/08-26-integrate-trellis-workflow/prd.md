# Integrate Trellis task and memory workflow

## Goal

Integrate the official Trellis task, spec, platform hooks, and workspace journal workflow into BalanceHub without committing local identity or runtime data.

## Requirements

- Use the official `@mindfoldhq/trellis` project layout and CLI at version 0.6.15.
- Enable the Codex and Claude project integrations generated by `trellis init`.
- Keep `.trellis/spec`, `.trellis/tasks`, `.trellis/workflow.md`, and the generated
  project integration files visible to Git so future sessions can recover shared
  conventions and task context.
- Keep developer identity, session/runtime state, local Claude permissions, and
  other machine-specific data out of Git.
- Record this integration as a Trellis task and session journal entry using the
  official scripts; do not introduce a parallel task or memory format.
- Do not put credentials, provider data, conversation secrets, or local paths
  into tracked Trellis artifacts.

## Acceptance Criteria

- [ ] `trellis platforms` reports Codex and Claude integrations.
- [ ] `trellis update --dry-run` reports the project is on the installed official
      version and preserves user data.
- [ ] Git sees shared Trellis specs/tasks/workflow and generated Codex/Claude
      integration files, while ignoring local identity/runtime/permission files.
- [ ] The task validates with `python3 ./.trellis/scripts/task.py validate`.
- [ ] A session journal entry records the integration and verification results.

## Notes

- Keep `prd.md` focused on requirements, constraints, and acceptance criteria.
- Lightweight tasks can remain PRD-only.
- For complex tasks, add `design.md` for technical design and `implement.md` for execution planning before `task.py start`.
