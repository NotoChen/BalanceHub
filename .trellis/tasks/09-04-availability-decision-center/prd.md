# 可用性决策中心

## Goal

让用户选择一个模型后，能够基于本地已有且来源明确的事实，比较哪些 Provider 与 Key 更适合立即使用，并直接进入现有操作流程。

## Requirements

- Rust 提供只读的可用性事实投影与排序，不由 Vue 拼接 Provider、Key、模型、测活和 Agent 配置得出结论。
- 候选项以稳定的 Provider ID + Key local ID 标识，不向前端返回 API Key、Token、Cookie 或密码。
- 模型、额度、Key 列表和测活分别记录来源、成功观测时间、新鲜度与 Key 归属。
- 未获取、过期和历史无归属证据分别表达；未知不得等同不可用，Provider 级模型观察不得伪装为任意 Key 已验证。
- 打开、筛选、排序和分页严格只读，不自动刷新、测活、切换 Key 或改写 Agent 配置。
- 排序优先级固定且可解释：精确 Key+模型实测成功、Key 明确支持、当前 Key 的 Provider 级模型观察、元数据可用但模型未知、明确禁用/过期/耗尽/缺失。
- 直接操作复用现有临时 CLI、当前 Key 选择、Agent 默认配置预览确认、模型详情和测活详情。
- 采用独立 feature/view；从搜索区上下文入口进入、替换主体，并在返回时恢复原面板搜索、滚动和焦点状态。
- 面板搜索与动态模型搜索是两个独立状态；未选择模型时展示选择空态，不写死默认模型。

## Acceptance Criteria

- [ ] 固定 Provider 观察输入在重启前后生成一致的事实与排序结果。
- [ ] 切换当前 Key 后，旧模型列表不会被归属为新 Key 的有效证据；历史无 Key 测活保持“未归属”。
- [ ] 所有候选解释均可追溯到事实来源和观测时间，未知/过期/失败视觉与语义可区分。
- [ ] 打开、搜索、筛选和分页不会产生网络、CLI、配置或存储副作用。
- [ ] IPC 快照不包含任何明文凭据，前端不重复实现排序和动作能力规则。
- [ ] 200 Provider × 2000 模型 × 100 Key 上限夹具下不预计算全量笛卡尔积，结果支持分页和过期请求拒写。
- [ ] 所有直接操作进入既有确认与执行链路，失败、超时和取消后不锁定工作区。
- [ ] macOS、Linux、Windows 均通过动态 Agent/Terminal 能力降级，不写死当前 Agent 数量。
- [ ] 376、600、930、1100px 下不横向溢出；窄窗口仍保留证据等级、额度、测活和 Agent 最小摘要。

## Out of Scope

- 自动刷新、自动测活或付费探测。
- 自动切换 Provider/Key、自动改写 Agent 配置或内置请求转发。
- 为可用性中心建立第二份 Provider/Key/模型全量数据库。

## Dependency

- 这是首个交付子任务，也是后续自动化规则的事实前置。
- 只处理本任务直接需要的类型拆分与后台任务契约，不进行无消费者的大范围重构。
