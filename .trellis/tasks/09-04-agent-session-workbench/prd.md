# Agent 会话工作台

## Goal

将会话检索、详情、恢复、运行实例和工作目录从临时 CLI 弹窗中提升为可持续使用的独立工作流。

## Requirements

- 按动态 Agent 能力展示工作区、搜索、详情、复制会话 ID 和恢复操作，不写死 Agent 名单。
- 搜索结果以会话为单位；关键词可命中标题、ID 和用户/助手正文，工具调用与工具输出不进入检索。
- 会话详情按消息流呈现正文与必要元数据，复杂工具数据默认折叠。
- 搜索取消按调用方 request ID、Agent 和工作目录隔离，不同查询不得相互取消或回写过期结果。
- 每个 Agent 的索引数据库与锁独立；一个 Agent 重建索引不得全局阻塞其他 Agent 查询。
- 恢复会话复用现有临时 CLI resume intent，工作台不得修改历史会话文件。

## Acceptance Criteria

- [ ] 两个不同 Agent、窗口或工作目录的查询不会相互取消或覆盖。
- [ ] 搜索始终返回会话列表，详情只在用户打开时加载。
- [ ] 所有声明会话能力的 Agent 均可展示详情并发起恢复；不支持者显示明确降级原因。
- [ ] 关闭或切换查询作用域后，旧结果不再回写，busy 状态始终释放。
- [ ] 各 Agent 索引大小、位置和生命周期设置保持独立且兼容现有配置。

## Out of Scope

- 修改、删除或跨 Agent 合并原始会话。
- 第一版全磁盘、全工作区无边界检索。
- 将 Provider 排序逻辑复制到会话工作台。

## Dependency

- 可独立于可用性页面实现；只依赖现有 Agent registry/session adapters。
- 实施前先完成搜索取消作用域化和索引锁拆分。

## Rollback Boundary

- 作用域取消和按库锁作为行为不变的基础步骤独立验证；工作台视图可单独回退到现有临时 CLI 会话入口。
- 回退不得恢复全局查询互相取消或跨 Agent 索引阻塞；不修改、迁移或删除原始 Agent 会话文件。
