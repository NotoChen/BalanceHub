工作方式

从接入账号，到真正跑通 CLI。

BalanceHub 不只回答“接口通不通”，而是把协议识别、账号观察、真实 CLI 测活和临时启动连成一条完整路径。

  1. 01

    接入中转站

    粘贴地址，识别 NewAPI、Sub2API 或通用 OpenAI 兼容 API，再按协议完成认证。

  2. 02

    验证真实可用性

    调用本机 Codex CLI、Claude Code、Gemini CLI 或 Grok Build 发起真实请求并记录结果。

  3. 03

    直接进入工作

    带上当前 Key、Base URL、模型与代理启动终端，或选择同目录的历史会话继续。

本地优先

配置由你保存，同步由你选择。

BalanceHub 是本地桌面工具，不是托管服务。账号密码、Cookie、Token、API Key 与站点配置默认由当前设备保存。启用 WebDAV 后，在本机加密并同步到你指定的服务；带认证的站点请求由本机 Rust 后端直接执行。

当前只支持 NewAPI、Sub2API 和通用 API Key；AnyRouter 按 NewAPI 方言兼容。 不提供 Web 自部署版本，通用 API Key 也不等同于完整账号登录态。

FAQ

开始之前，最常见的三个问题。

遇到协议或具体站点问题，请在 GitHub Issues 提供可复现信息；仓库目前只接受 Issue，不接受 Pull Request。

为什么系统提示未知开发者？

安装包通过 GitHub Releases 分发；若系统尚未建立对当前发布者的信任，macOS 或 Windows 可能显示系统信任提示。

CLI 测活会消耗额度吗？

会。测活调用本机独立 CLI 发起真实请求；首次开启自动测活前，应用会明确二次确认。

API Key 额度和账号额度一样吗？

不一定。API Key 模式展示的是 Key 维度额度，部分站点还会返回无限额度；它不代表完整账号登录态。
