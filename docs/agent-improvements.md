# Agent 管理改进与验收

本轮参考 [Magpie](https://github.com/yetone/magpie/tree/657e48ab) 的实现思路，扩展 BalanceHub 已有的资产库、配置事务、会话索引和任务界面。以下七项已接入代码；配置功能的实际使用效果由用户在隔离开发版验收。

## 第一阶段实施范围

| 方向 | 操作入口 | 已接入的改进 |
| --- | --- | --- |
| 读取与扫描 | Agent 总览、资产和配置来源 | 一次扫描内复用路径观察、文本读取与解析结果，写入前重新校验 |
| 工作规则 | Agent → 工作规则 | 通用规则与可选的 Agent 专用补充，保存模板后预览并应用，支持 Diff、移除已写入规则和 WebDAV 同步 |
| MCP 诊断 | MCP 详情 → 连接状态 → 检测连接 | stdio / Streamable HTTP / SSE 检查、阶段状态、取消和工具搜索 |
| WSL | Agent → 环境；历史会话的环境筛选 | 发行版检测、按需启动、配置文件、会话检索与原生继续 |
| 模型资料 | 中转站可用模型窗口、临时 CLI 模型选择 | 上下文、输出上限、能力、模态和公开价格资料 |
| 原生会话用量 | 历史会话 → 详情 → 用量 | 从原生日志增量提取用量，合并重复记录，按已知模型资料估算费用 |
| 配置读写 | 原生配置和资产定义编辑器 | 保留 BOM、行尾和原生格式，补全文件身份、硬链接及权限校验 |

本地协议网关与多账号路由需要独立的产品与运行时设计，不在这份 Agent 管理改进中混入。

## 行为与边界

### 读取与扫描

- 复用已有索引和缓存，在单次同步读取范围内减少相同文件的重复读取与解析；外层读取结束后释放临时缓存。
- 路径观察最多 16,384 项，解析缓存预算 8 MiB，避免扫描过程持续占用内存。
- 文件指纹和写入前检查使用新的观察结果；权限、授权和文件句柄不作为扫描缓存复用。
- 本轮没有执行大规模性能基准，不提供未经测量的提速百分比。

### 工作规则

- 页面上方的“Agent 规则”直接展示原生配置发现返回的规则文件，无需先创建模板。文件名、所属 Agent、作用范围和查看／编辑入口集中在同一行；路径单独展示，长路径可悬停查看完整内容。可按 Agent 筛选、按文件名或路径搜索，编辑沿用现有 Diff 流程。
- 已有规则与规则模板采用两个紧凑列表区块；没有规则的 Agent 合并提示，不再各占一个空区域。搜索未匹配、尚在读取、读取失败和文件信息待刷新分别展示，不把搜索结果为空误报成没有规则。读取说明与模板使用说明收在对应的帮助入口中。
- 原生来源由 Rust 返回内容状态，复用本次扫描已捕获的字节；零字节、只有空白或 UTF-8 BOM 的文件标为“空文件”，不计入已填写规则数量，但保留“编写规则”入口。Agent 卡片与模板应用目标使用相同的空文件标识；无法读取内容的来源不会被判定为空。摘要缓存结构版本同步更新，避免复用没有内容状态的旧摘要。
- 默认读取当前配置范围：用户规则来自各 Agent 的实际配置目录，选择项目后同时展示原生发现支持的项目规则和上层规则；Windows 可查看正在运行的 WSL 发行版内的用户规则。已确认不存在的候选文件不混入已有规则，读取失败的来源保留具体原因。
- 已有规则列表复用原生来源缓存，首次读取、来源失效或手动刷新时重新获取；打开正文前重新校验文件。已有规则和模板应用共用同 Agent 的读取队列，关闭或切换应用目标时取消旧请求。读取规则时不连带刷新后台的 Agent 总览或全量资产。
- 在“工作规则”页新建规则，例如回复语言、代码风格、项目约定和操作边界。编辑器优先展示“通用规则”，各 Agent 的“专用补充”为可选区域，按需展开编辑。
- “保存模板”将规则保存在 BalanceHub 的共享库，可随 WebDAV 同步；保存后显示“应用到 Agent”入口。保存模板不会自动写入 Agent 文件，修改模板后也需要重新应用。
- 点击“应用到 Agent”，直接选择 Agent 和原生规则文件。文件选项展示完整路径、作用范围及文件状态，再通过“预览并应用”进入既有编辑与 Diff 流程，确认保存后才写入文件。WSL 环境选择仅在 Windows 显示。
- 写入使用管理区块，保留原文件区块外的正文。发现原生内容已变化时要求合并；损坏或重复的管理标记不会直接覆盖。
- Codex 已存在 `AGENTS.override.md` 时优先使用它；创建默认指令文件使用 `AGENTS.md`。
- “移除文件中已写入的共享规则”位于应用窗口的展开项，只移除所选文件中由 BalanceHub 写入的内容。删除模板会保留已写入 Agent 的规则。
- 编辑器可关闭并保留草稿；保存结果通过 revision 校验，旧请求不会关闭新草稿或覆盖更新后的列表。
- 列表展示规则摘要和已填写专用补充的 Agent；搜索同时覆盖规则名称、通用规则和专用补充。保存结果仅表示模板已保存，不标为 Agent“已生效”。

参考 [Magpie 的指令页面](https://github.com/yetone/magpie/blob/657e48ab/internal/gui/assets/library.js#L1079)，其页面同时列出共享内容、正在使用的方案、各 Agent 的目标文件、开关和专用补充；保存会写入已开启 Agent 的文件。BalanceHub 沿用现有逐次预览与确认流程，借鉴其内容与应用对象分层的呈现方式，并明确标注保存模板与应用文件之间的关系。

2026-10-13 展示与空文件识别调整已通过 `npm run build`、Rust 格式检查、strict Clippy 和差异检查；全 App 的 9 处 Popover 已静态核对内容插槽。隔离开发版已完成 Rust 重编译并启动。配置写入与实际桌面效果仍按仓库约定由用户验收，重点检查：

- 新建时先看到通用规则，专用补充按需展开；关闭后可继续草稿，保存成功后有明确的应用入口。
- 未创建模板时也能看到原有规则；切换 Agent、项目范围及可用的 WSL 环境后，路径与正文应对应所选来源；查看原文不写入文件，编辑后通过 Diff 确认保存。
- 窄窗口下文件操作应换行留在文件旁，长路径不应撑出内容区；已有规则、模板、空状态和帮助内容在浅色与深色主题下均应清晰可读。
- 帮助正文默认不占页面空间，点击对应的信息按钮后才显示；空规则文件显示“空文件”与“编写规则”，顶部和 Agent 筛选数量只统计有内容的规则文件。
- 应用窗口直接列出 Agent 和规则文件；长路径可换行，文件范围、不可写原因和本次使用的内容可见。
- 读取期间可关闭窗口或更换应用目标，旧结果不回写到新选择；失败和超时后忙碌状态应释放。
- 空白规则引导返回编辑；写入前仍需核对 Diff 并确认，删除模板与移除文件中的共享规则含义明确。

### MCP 连接诊断

- 仅在点击“检测连接”后连接远程服务或启动本地 MCP，执行初始化、协议协商和工具列表读取，不调用具体工具。
- 支持 stdio、Streamable HTTP 和旧 SSE；协商版本涵盖 `2024-11-05`、`2025-03-26`、`2025-06-18`、`2025-11-25`。
- 前端展示阶段、耗时和结果，支持取消。后台任务限制总时长和并发数，并负责本地进程、HTTP 会话的结束清理。
- 工具列表展开后才渲染，每页 50 项，搜索和重新检测重置页码；协议读取上限为 5,000 个工具。
- 复用 App 的代理解析。支持配置中的环境变量引用；不执行 `headersHelper`，不复用 Agent 私有 OAuth 会话。需要这些认证方式或使用 WebSocket 的连接会说明需要回到原生 Agent 检查。

### WSL 环境

- Windows 的“检测环境”仅探测正在运行的发行版。已停止的发行版保留已有结果，点击“启动并检测”才启动指定发行版。
- 本机与各发行版使用独立的配置来源身份和授权代次。配置编辑、Diff 和写入复用既有配置事务。
- 支持 Linux 路径与 `\\wsl.localhost\…` / `\\wsl$\…` 的映射，保留 Linux 路径大小写；文件访问、写入和继续会话前复查发行版状态。
- 历史会话可按环境筛选。WSL 来源后台更新后通知会话列表和统计，不因切换页签重新扫描所有来源。
- 继续 WSL 会话沿用发行版内的 Agent 配置；本轮尚未接入 WSL 临时中转站切换，也不将 Linux CLI 记为 Windows 的首选安装。
- “环境”入口及 WSL 选择项仅在 Windows 显示。macOS / Linux 不展示 WSL 空面板，也不发起发行版检测；若热更新前停留在该页，会自动回到总览并清理无效的 WSL 筛选。平台判断复用后端系统类型查询，成功结果在前端共享缓存。
- Windows 交叉编译已通过，WSL 启停、UNC 读写和终端继续仍需 Windows 实机验收。

### 模型资料

- 资料来自 models.dev，缓存 24 小时；并发刷新请求合并，失败后退避，避免多个窗口重复下载。
- 资料只补充模型说明。当前 API Key 的可用模型仍由中转站返回，资料缺失不阻止选择已有模型。
- 同名模型存在歧义时不随意套用某个供应商的资料。公开价格仅用于参考，实际能力与费用以中转站为准。

### 原生会话用量

- Claude、Codex、Gemini 和 Grok 的用量随既有会话索引增量读取，不为展示用量另做一次全量扫描。
- Claude 按消息与请求标识去重；Codex 支持累计值及 `thread_token_usage` 记录；Gemini 的消息更新和回退同步清理对应用量；Grok 读取原生 turn / modelUsage。
- 缺失字段显示未知，计数回退、索引未完整和无法可靠归属模型的记录保留不完整状态。累计计数发生模型切换时不全部归到最后一个模型。
- 展开“用量”后才读取参考价。只能定价部分记录时显示“已知部分参考估算”，无价格资料不按零费用处理。
- 本轮没有宣称覆盖所有原生日志变体或精确逐次请求计费；展示的是日志可确认的用量与公开价估算。

### 配置文件读写

- UTF-8 BOM 不进入编辑正文，保存时恢复；统一 CRLF 的文件保持 CRLF，混合行尾不强制统一。
- JSON / JSONC / TOML / dotenv、原生配置及相关资产编辑共用文本与布局处理，保留原有注释和编辑范围外的内容。
- 通过已验证的文件句柄识别硬链接；会拆开链接关系的原子替换会拒绝执行。
- Unix 保存文件所有者、组和模式；无法保持所有者时明确失败。Windows 保留 reparse 校验与 `ReplaceFileW`，文件身份接口回退后仍拒绝无效的全零身份。
- 本轮没有增加跨平台完整 ACL / 扩展属性保留协议。

## 验证约束

- 按仓库 `AGENTS.md`，Agent 配置由用户验收；本轮不新增或运行其自动测试，不写合成配置，不执行桌面自动验收。
- 构建与静态检查使用仓库共用 target，同一时间只运行一个重型 Cargo 任务。
- 开发版使用独立应用标识和配置目录；安装版不参与源码验证。
- Windows / WSL 运行行为需要实机确认，静态检查不能替代实机验收。

### 维护任务与恢复

- 确认预览后关闭发起弹窗，进度、取消及逐项结果进入后台任务中心。取消停止尚未完成的操作；已写入的内容保留，失败时明确区分未修改和部分修改。
- 预览绑定窗口和一次性令牌，有效期 5 分钟。关闭、切换来源或请求超时后，迟到的预览会释放，旧结果不覆盖新选择。
- 更换恢复文件、批量目标或迁移目录后，正在准备的旧预览失效；收起共享版本历史后，迟到的比较结果不会重新弹出。变更文件列表每页显示 50 项，选中文件后才读取完整 Diff。
- 后端返回任务实际影响的刷新范围：共享版本与来源更新只使资产库失效，MCP 和批量操作只刷新所涉及 Agent 的总览及配置来源；会话迁移通过会话事件刷新。不产生变更的失败或取消任务不触发这些刷新。
- 原生文件写入、移除及原生 CLI 的可读取配置文件保存操作前快照。快照表示修改前内容，是否完成以后台任务结果为准。
- 本地快照按内容哈希去重，保存在应用独立数据目录，不进入 WebDAV 数据包。恢复前重新读取当前内容并生成 Diff；原生配置变化时停止旧预览，不覆盖新的文件。
- 单次恢复可选择全部或部分文件；二进制内容以字节数及 SHA-256 展示。恢复内容的内存预算为 256 MiB，超出时可在文件选择中分批恢复。
- 恢复目录时先完成文件和链接，再从子目录到父目录恢复权限，避免只读父目录阻止后续写入。历史恢复覆盖文件内容和已记录的目录链接；写入期间自动创建的空父目录可能保留。
- 共享库保留最近 32 个版本及仍被配置记录引用的版本。恢复共享版本或接受上游版本后，再由用户选择需要更新的 Agent。

### Skill 内容与来源

- 完整 Skill 包支持单文件 16 MiB、整包 64 MiB、8,192 个文件及 32 层目录。浏览缓存复用未变化文件的内容，提交前仍核对文件身份和原始内容。
- 便携 Skill 包跳过 `.git`、`node_modules`、`__pycache__` 和 `.venv`。移除预览会检查待删除目录的完整内容，不因分发时忽略目录就未经预览递归删除。
- 共享库使用独立内容文件和版本引用，同一文件被多个资产或版本使用时只保存一份；原有存储在下次保存时转换。WebDAV 的预览、保存与恢复日志使用同一存储格式。
- 来源支持公开 GitHub HTTPS 仓库，可自动读取 Git 仓库、Git worktree 和常见 Skill 安装锁文件提供的来源信息。缺少可靠来源时允许手动填写仓库、目录及分支。
- 检查更新按 Skill 所在目录查询最新提交。下载固定到提交版本，并核对 Git blob 哈希与长度；关闭来源面板或切换资产会取消请求。
- 来源信息随共享 Skill 同步；下载后先比较，再保存为新版本。私有仓库、其他代码托管平台和自动覆盖 Agent 配置未接入本阶段。
- 未运行大型目录性能基准，不将缓存与存储调整描述为已测得的提速比例。

### 批量与 MCP 工具

- 每批最多 128 个资产。选择范围内的不可操作项单独说明原因，其余资产可以继续选择；提交前重新核对全部选择，共用文件的修改先合并再写入。
- 路径锁复用同一真源。Windows 普通路径按不区分大小写比较；WSL 路径保留 Linux 目录大小写，`wsl$` 与 `wsl.localhost` 的同一路径统一识别。
- MCP 工具策略使用 Claude 的 `permissions.deny`、Codex 的 `disabled_tools` 和 Gemini 的 `excludeTools`。原有的 deny 规则、其他作用域限制及工具白名单继续保留。
- 启用操作只撤回 BalanceHub 添加的停用项；原配置仍有限制时给出具体原因。工具归属记录保留在当前设备，不随共享 MCP 同步到其他设备。
- Gemini 的 `includeTools: []` 表示不包含任何工具；带参数说明的白名单按原生实现识别。不能把未知 Agent 的字段格式当作已支持的单工具策略。
- 工具列表与连接诊断共用 5,000 项读取预算，每页显示 50 项；不通过列出资产或查看工具列表自动调用 MCP 工具。

### Claude 项目迁移

- 新项目目录必须已存在；目标项目历史目录必须不存在。跨 Agent、跨 WSL 发行版或与已有目标历史自动合并不属于本次迁移。
- 先准备暂存内容，再核对原始文件集合和哈希，最后执行不覆盖目标的目录移动。第二次移动失败时尝试还原原目录；失败或取消时清理尚未发布的暂存内容，保留迁移记录及原始备份。
- 原始备份位于该 Agent 配置根目录的 `balancehub-session-relocations/<任务标识>/original`，任务详情显示位置。原始备份位于会话扫描目录之外，保留会话 ID 与消息原文。
- JSONL 流式处理，修改顶层 `cwd` 及会话索引的路径字段，不重写消息正文。单条记录或索引预算为 64 MiB，整项目文件数量预算为 32,768 项。
- 正在运行的已知项目实例、最近一分钟内仍写入的历史、链接、损坏记录和无法可靠编码的超长项目路径会阻止迁移。外部客户端无法完全自动识别，因此开始前需关闭该项目的 Agent 与编辑器。
- 目录切换完成后取消旧来源的检索并使其缓存失效，通知会话列表刷新。最终目录切换期间只暂时停止任务取消，其他弹窗与主界面仍可操作。

### 第二阶段验收

本阶段的检查结果单独记录，不复用前一阶段的 CI 或测试结果。Agent 配置的真实写入和桌面效果按 `AGENTS.md` 交由用户验收。

本阶段收尾检查：

| 检查 | 结果 |
| --- | --- |
| `npm run build` | 通过 Vue / TypeScript 检查与 Vite 构建 |
| `cargo fmt --all -- --check` | 通过；宏声明的 Agent 模块另外逐文件执行 Rust 格式检查 |
| `cargo clippy --all-targets --all-features --locked -- -D warnings` | macOS 通过 |
| `cargo xwin check --cross-compiler clang --target x86_64-pc-windows-msvc --all-targets --all-features --locked` | Windows x64 交叉检查通过 |
| `npm run doctor:platform` | 平台脚本变量与构建缓存静态检查通过 |
| `git diff --check` 与新增文件空白检查 | 通过 |
| 隔离 `tauri dev` | 修正后完成重编译，窗口为“BalanceHub · 会话开发版” |

Windows 检查发现并修正了 Hook 核对方法和原子写入结果的 Unix 条件编译遗漏、删除句柄的 API 类型以及跨平台错误类型推断；共享库的旧 Windows 写入分支同步移除，改用共用写入实现。原生 Hook 与批量 Hook 的文件分组统一使用路径标识，保留 WSL 文件名大小写。

检查共用仓库 target，2 个 Cargo 编译任务串行执行，关闭调试符号和增量缓存。收尾可用磁盘约 53 GiB，target 约 4.2 GiB。前端仍有原有 TOML 格式化器 chunk 体积提示，Windows 资源编译仍有工具链未使用 `-L` 参数的提示；两者均未阻断上述检查。

本阶段没有新增或执行 Agent 配置自动测试，没有写入合成 Agent 配置，没有进行桌面自动验收。`--all-targets` 仅编译检查既有测试目标，不执行测试。隔离开发版标识为 `com.zangbai.balancehub.sessionreaderdev`，使用独立配置副本。

- 重点验收：大型 Skill 读取、同文件批量操作、取消与过期预览、配置历史选文件恢复、共享版本 Diff、来源更新、MCP 原有规则保留及 Claude 项目迁移。
- Windows 的 junction、符号链接权限、文件占用及 WSL 读写仍需相应环境实机验收。
