# 中转站配置

BalanceHub 当前支持 NewAPI、Sub2API 和通用 API Key。AnyRouter 这类站点按 NewAPI 接口方言处理，不在界面上作为独立中转站类型展示。

中转站配置和凭据只保存在当前电脑的应用数据目录中。导出配置会包含中转站信息和凭据，请只在可信设备之间迁移。

## 认证方式

NewAPI / Sub2API 新配置默认使用账号密码。账号密码可以登录站点，并按需补全后续会话、访问令牌和 API Key；已有凭据时也可以按协议直接选择 Cookie、访问令牌或 API Key。通用 API 只使用 API Key。

### 协议边界

- NewAPI：支持账号密码、Cookie、访问令牌和 API Key，并按站点能力提供签到、日志、用量、密钥管理等功能。
- Sub2API：支持账号密码、Access / Refresh Token 和网关 API Key，并提供用户资料、额度、用量、日志和密钥管理能力。
- 通用 API Key：通过 OpenAI 兼容 `/v1/models` 接口验证和同步模型，不提供账号、签到或站点密钥管理能力。

### 账号密码

账号密码适合首次配置或希望由应用建立会话的场景。应用只在登录站点时使用账号密码，登录成功后缓存 Session，并可继续补全访问令牌和 API Key。

### Cookie

Cookie 适合完整账号能力，包括读取账号信息、额度、签到、API Key 管理、请求日志等。

使用 Cookie 时，用户 ID 可以由应用自动解析，通常不需要手动填写。

### 访问令牌

访问令牌适合不想长期使用 Cookie 的场景。使用访问令牌时，用户 ID 需要明确填写或由同步流程补齐。

如果当前中转站支持令牌创建，但本地配置里缺少令牌，应用会在需要同步时提示是否创建，不会静默创建。

### API Key

API Key 只适合 Key 维度的额度查询和相关操作，不等同于账号登录态。

使用账号凭据补全配置时，应用会先读取并保存站点已有的 API Key（最多 100 个）。存在多个 Key 时会保留完整列表，并要求选择本卡片用于额度刷新、模型请求和未单独指定场景的“当前调用 Key”；只有确认列表为空时才提示创建。保存后的中转站可在“编辑中转站 → 认证凭据”中直接完成同步、添加、创建、备注、复制、删除和当前调用 Key 切换，不再叠加第二个管理弹窗。纯 API Key 认证只维护本地 Key，不提供站点同步操作；卡片中的管理按钮会直接打开这一页。曾由账号同步、但当前已没有站点管理凭据的 Key 仍可仅从当前卡片移除，站点令牌不会因此撤销。Key 的新增、备注、切换和删除会立即保存，编辑器底部的“保存中转站”只负责其余配置草稿。每个 Agent CLI 的默认配置仍可独立绑定其中一把 Key，不受当前调用 Key 限制；被 Agent 使用的 Key 需要先切换绑定才能删除。

使用 API Key 时要注意：

- 不支持签到。
- 不代表账号总额度。
- 某些中转站返回的 Key 额度上限可能是无限。

## 连接测试

测试连接会尽量完成这些检查：

- 中转站地址是否可访问。
- 站点信息是否可以读取。
- 当前认证方式是否有效。
- 账号或 API Key 额度接口是否可用。

如果测试连接拿到了额度结果，应用会缓存这次结果，保存后卡片可以直接展示最新额度。
