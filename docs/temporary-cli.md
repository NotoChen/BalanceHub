# 临时 CLI 启动设置

从中转站卡片的 **临时 CLI**，或 Agent 卡片的 **启动** 进入。左侧选择工作目录或历史会话，右侧选择 Agent、终端、模型和 API Key，再调整会话配置。底部持续显示启动目录和启动按钮。确认页展示设置摘要与启动命令，确认后关闭弹窗，启动结果进入后台任务。

常用目录以名称展示，同名目录附带路径，悬停可查看完整路径；移出记录的操作在悬停或键盘聚焦时显示。其他目录可直接浏览、输入路径，或通过系统目录选择器打开。目录与配置区分别滚动；查看历史会话详情和选中会话继续仍是两个独立操作。

## 会话配置

| 页签         | 内容                                                                                                |
| ------------ | --------------------------------------------------------------------------------------------------- |
| 模型与上下文 | 推理强度、上下文窗口、自动压缩阈值、思考预算、单次输出上限。按所选 Agent 和模型提供原生支持的设置。 |
| 权限与工具   | 将沙盒范围、操作审批、可用工具集合、免确认规则、禁止规则与始终确认规则分开设置。                    |
| 资产         | 按类型选择保持当前配置或本次停用，再逐项选择 Skill、MCP、插件或扩展。Hook 通过整类设置控制。        |
| 会话         | 会话记录保留、可选名称、启动任务、本次工作要求、原生规则加载与额外可访问目录。                      |

参数以紧凑的设置行展示，轨道和数值并排；推理强度保留原生档位的小刻度，上下文窗口、压缩阈值等数值可直接精确输入。读取到默认值时，数值框直接显示实际值；拖动、点击档位或编辑数值后才覆盖本次参数，并显示 **取消覆盖**。没有配置也没有固定默认数值时显示“未设置”，配置读取失败单独显示“读取失败”。未设置和默认行为不使用警告样式；必要的行为说明放在详情中，滑块不会标出假定位置。没有明确原生档位的选项保留自由输入。

数值滑块优先根据原生模型资料选择便于拖动的区间，输入框遵循后端声明的实际数值范围。Codex 上下文窗口和压缩阈值共用 token 刻度，轨道两端显示范围；压缩比例以当前窗口计算。没有原生上限的参数可以输入超出当前刻度的值，滑动区间会随之扩展；滑块终点不代表服务端容量。拖动即时跟随，点击档位和取消覆盖时平滑过渡；系统启用减少动态效果时关闭动画。

点击参数名称旁的信息图标，可查看 **配置键、当前值、解析状态、原文值、读取来源和本次选择**；**取消覆盖** 会撤销这一项的本次选择，并展示取消后的值与依据。下拉默认项直接展示此时会使用的值，旁边标明取值状态。读取不到具体默认值时，详情说明缺少的模型资料、账号信息或不可读的配置来源，不把说明文字当作原文值。管理策略固定的参数会说明原因。

模型选择中的默认项与本次手动选择分别计算，选择其他模型不会改变“取消覆盖后使用什么模型”的显示。启动预览复用同一取值结果；没有调整运行参数时只读取模型配置，不为补充这项说明触发模型网络查询或资产扫描。

这些选项通过本次进程参数、环境变量或临时配置传递，不写入 Agent 的全局配置。资产勾选表示保留原生配置，不会启用原本在 Agent 中停用的资产。

需要保存为 Agent 长期默认值时，可从 **Agent → 总览** 中卡片底部的 **配置** 进入[原生配置表单](agent-settings.md)。两处共用字段解析和滑块：临时启动的 **取消覆盖** 只调整本次启动参数；原生文件编辑的 **移除设置** 修改草稿，通过 diff 预览确认后写入选定文件。

中转站的 CLI 模型偏好和上次选择仅用于预填，仍可在本次更换或清空。清空后不再从后台补回模型偏好，由 Agent 选择原生模型；后台测活模型不参与交互启动。代理继续使用 App 的统一代理设置。

模型选择器中，**中转站模型** 与 **Agent CLI 模型** 分开查看。前者来自中转站的模型查询，权限可能因 API Key 和分组不同而变化；后者来自 CLI 模型目录、原生别名与已有配置。切换列表只切换查看来源，不修改已选模型，也不会把两份列表合并成“都可调用”。两处均允许搜索和手动输入 ID；继续历史会话也使用相同的选择器。代码审查模型与子 Agent 默认模型同样可以选择两种来源。

CLI 模型名单动态读取，Agent 更新后会根据安装文件变化自动重查。列表先显示缓存，后台刷新结果正常保留 5 分钟，失败后 1 分钟可重试；列表右上角提供立即刷新。查询失败不会清空已选模型或锁定启动窗口，也不会重新扫描资产。各 Agent 的具体读取来源和适配范围见[可视化配置说明](./agent-settings.md#模型目录的来源与更新)。

**模型与上下文** 也提供原生模型映射：Claude 可为各档位和子 Agent 覆盖实际模型及档位显示名称；Gemini 可新增或覆盖自定义别名和继承关系；Codex 可分别选择审查模型与子 Agent 默认模型。Grok 可以选择已有别名，映射编辑在用户级 Agent 配置中完成。具体范围见[模型别名、映射与用途](./agent-settings.md#模型别名映射与用途)。

映射修改后，在后台重新解析相关模型参数与候选项，保留已填写内容；校验错误不会禁用整个配置区，可以继续修正。取消单行覆盖时保留其他映射与参数，按剩余设置和 Agent 配置计算结果；清空目标模型时仍保留该行的继承和显示名称。启动摘要用“别名 → 实际模型”展示，命令预览继续显示对应的原生参数和临时配置。

同一启动窗口内，模型选择和会话参数按 Agent 分别保留。切到其他 Agent 再回来，会恢复该 Agent 的本次草稿，包括清空模型选择、由 Agent 选择模型的状态；切换到历史会话后再返回新会话，也会保留原来的新会话模型。

## 上下文容量与推理

上下文窗口表示模型能够处理的 token 数；工作规则和启动任务在「会话」页单独设置。

| Agent  | 上下文与生成参数                                                                                                                                                    | 推理选项的来源                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Codex  | 支持本次覆盖 model_context_window、model_auto_compact_token_limit。                                                                                                 | 读取配置指定的 model_catalog_json，或原生缓存与当前 CLI 的内置模型目录；没有对应模型资料时提供官方参考值，并允许输入原生值。 |
| Claude | 支持自动压缩窗口与输出上限；CLAUDE_CODE_MAX_CONTEXT_TOKENS 可用于无法识别的网关别名。已识别 Claude 模型的窗口由模型和账号决定，不能把该变量单独设置后当作已经生效。 | 读取本机 --effort 帮助，结合已识别的模型及本机管理上限提供选项。                                                             |
| Gemini | 显示模型窗口的原生限制，支持压缩百分比、指定模型的思考 token 预算、推理级别和输出上限。                                                                             | 使用该模型支持的原生枚举或预算。推理级别与思考预算互斥，面板和启动检查都会提示。                                             |
| Grok   | 展示原生模型窗口、压缩比例与输出上限。当前公开的 CLI 未提供这些值的可靠单次覆盖入口。                                                                               | 原生 --reasoning-effort，允许填写所选模型支持的值。                                                                          |

指定较大的上下文值不会扩展服务端的模型容量。Gemini 的压缩输入使用百分比，例如 50% 对应原生 model.compressionThreshold = 0.5；生成参数只作用于选定模型的主会话，不重写辅助模型配置。

Codex 未显式配置上下文窗口时，会继续读取模型目录的默认值。缺少本地模型缓存时，通过所选 CLI 的 `debug models --bundled` 读取随该版本提供的目录；此操作不联网、不创建会话，并按 CLI 文件状态缓存结果。本地目录文件也按文件状态复用解析结果。显式指定的模型目录保持优先，不混入其他目录的数据。通用模型介绍中的容量不作为 Codex 的原生默认窗口。自动压缩阈值按原生规则取上下文窗口的 90%，配置或模型目录的更小阈值优先；面板同时展示 token 数及占比，修改本次窗口时同步重新计算。它与模型的输入可用窗口比例分别计算。

Claude 的推理强度与压缩窗口通过其官方环境变量覆盖，避免已有同名环境变量盖过 CLI 参数。未覆盖时仍保留原生模型、账号及组织策略的行为。

Codex 还提供回答详细程度、推理摘要、服务层级、代码审查模型、子 Agent 默认模型与推理强度、Agent 中断消息及登录 Shell。子 Agent 并发数按当前模型的原生后端显示：V1 默认 6 个子 Agent，V2 默认 3 个子 Agent 加 1 个主 Agent；V2 专用的总线程设置会自动换算。这些值只有在明确修改后才作为本次启动参数传入。

## 会话保留与工作目录

工作目录仍然是所选项目目录。关闭 **保存会话** 只隔离原生会话状态，并不把整个项目复制到临时目录，也不撤销 Agent 对项目文件的修改。

Codex、Claude 和 Gemini 使用各自支持的配置目录环境变量，将本次会话记录写入独立目录。Codex 还将 SQLite 索引、日志和输入历史指向该目录，并关闭常驻 daemon。正常退出会清理目录；异常中断后的残留由退出记录核对和后续启动清理处理，运行中的会话不会按目录年龄直接删除。

Grok 的交互会话由常驻进程管理，本版保留它的原生会话记录，界面会说明原因。原生 CLI 能力随版本变化，无法确认支持的选项不会作为可用开关展示。

后台测活继续使用隐藏的非交互 CLI 和独立目录，不使用这里保存的交互启动方案。

## 资产控制的差别

- **Codex**：使用原生 Skill、MCP 和插件开关，保留已有 Skill 禁用规则。插件提供的 MCP 随所属插件控制；要整类关闭 MCP 时，如果仍有这样的插件启用，会提示同时停用对应插件。
- **Claude**：整类关闭 Skill 使用原生 slash-command 开关；单个 Skill 使用调用禁用规则。单个 MCP 使用原生服务名称禁用规则，保留其连接定义、认证和插件命名空间。关闭全部 MCP 使用原生严格配置模式；组织托管 MCP 不允许这种替换时会明确提示。
- **Gemini**：使用原生 Skill、MCP、扩展和 Hook 配置，保留原有禁用列表与系统策略。扩展支持整体关闭和逐项选择。
- **Grok**：本版按 Agent 当前配置加载资产，提供权限模式、沙盒、工具白名单与规则、工作要求、推理强度、网页搜索、网页读取、子 Agent、记忆与其他原生功能设置。

资产列表只在进入「资产」页时读取当前 Agent 和当前目录，并复用未变化的来源；切回已读取的空列表也不会重新扫描。切换目录会重新核对对应范围。部分来源不可读时会显示说明；依赖完整清单的整类操作不会把不完整扫描当成已全部停用。

切换配置页签时保留资产搜索和类型筛选。刷新后已不存在的类型会自动回到全部，空结果可直接清除筛选；点击资产名称或复选框均可调整本次选择。

## 继续历史会话

继续已有会话会保留其记录，不提供清除原会话的开关。此次补充的工作要求和任务作为新的上下文发送，不改写旧消息；跳过工作规则也不会清除历史中已有的上下文。

中转站临时 CLI 和会话历史的继续入口都可选择本次模型。留空时使用原会话模型；明确选择后，Codex、Claude、Gemini 与 Grok 使用各自的原生模型参数继续，启动预览与实际命令保持一致。历史模型只作为未覆盖时的参数解析依据，不自动变成模型覆盖。未覆盖的其他会话参数由 Agent 从原记录恢复；面板中的当前值来自所选目录的启动配置，不能代替原生会话内的全部状态。

已有活动实例时，默认设置可以返回原终端。修改过本次设置时会提示先退出原会话，再通过新进程应用设置，避免把原终端当成已经应用了新配置。

WSL 历史会话使用发行版内的原生启动配置，可明确指定本次模型；本机模型目录不会混入 WSL 的模型建议。

## 保存启动方案

在 **保存方案** 中命名并保存当前选项。方案按 Agent 区分，支持更新、另存和删除；选择方案后仍可继续调整本次设置。方案保存在 BalanceHub 本机配置中，包含所填写的工作要求、任务和附加目录。

已选方案发生修改时，入口显示 **保存修改**；保存后或恢复到原方案时，该状态会消失。未改动的方案不会重复提交保存。切换 Agent 时也会保留所选方案和尚未保存的方案名称。

打开窗口使用已有 CLI 检测结果。安装新 CLI 或更改路径后，可使用 **重新检测** 更新列表。已保存的方案在启动前仍会核对当前 CLI 能力和资产来源；过期的选择需要先调整。
