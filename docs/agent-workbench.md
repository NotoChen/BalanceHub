# Agent 工作台

主面板顶部的 **中转站 / Agent** 开关用于切换管理视角。中转站卡片保留额度、签到、Key、日志和临时启动；Agent 工作台集中管理本机 CLI、各 Agent 的资源和运行实例。已有的用户配置、第三方资源和插件附带资源都可以进入盘点与管理，具体动作取决于原生能力和来源权限。

本文描述当前仓库源码中的工作台。已发布安装包的功能以 [更新记录](https://github.com/NotoChen/BalanceHub/blob/main/CHANGELOG.md) 为准。

## 扫描与更新范围

各界面复用同一份资产目录。单张 Agent 卡片的刷新只刷新该 Agent 的摘要与可见历史；资产目录另行按来源变化更新。失效标记不会立即重扫其他工作目录，当前可见页面按需更新。

展示扫描按变化的 Agent 更新，并在内存中复用未变化的普通文件。每次复用都会核对文件身份、时间戳、权限和路径边界；缓存最多 16 MiB、2048 个文件，不保存到磁盘。目录新增、删除、共享链接及缺失来源仍按实际文件系统核对。写入前后校验不使用这一展示文件缓存。

开发版的“Agent 展示扫描”日志记录本次 Agent 数、缓存命中数、实际文件读取数、读取字节和耗时，不记录配置正文。不能仅凭前端出现刷新状态判断是否发生全量扫描。

## 安装渠道与升级

“版本与路径”管理已安装 CLI 的升级；未安装时提供官方安装说明，目前不提供统一的一键安装。

- npm 全局安装：使用 `npm install --global <包名>@latest`，限定已验证的包名、运行时和原全局前缀；不使用会受原 semver 范围限制的 `npm update -g`。
- 官方原生安装：Claude 使用 `claude update`，Grok 使用 `grok update`，沿用各自的更新渠道与版本策略。普通升级不传具体版本、不切换 stable/latest/alpha；目前原生识别限定 macOS。
- Homebrew：识别官方 `homebrew/core` Formula 与 `homebrew/cask` Cask 的安装记录及包目录，按所选包调用 `brew upgrade --formula` 或 `brew upgrade --cask`。版本检查复用 Homebrew 官方 API 缓存，确认及执行前核对本地包身份、固定状态和安装记录。暂不支持自定义 tap 或无法验证的安装布局。

Homebrew 可能安装或更新配方要求的依赖。只读检查关闭自动更新元数据；确认升级后允许 Homebrew 正常刷新元数据，关闭自动清理和额外依赖方升级。检查时的可用版本只作提示，不作为指定安装版本。不同渠道之间没有自动回退：npm 失败不会改用原生安装，Homebrew 失败不会改用 npm。Node 由 Homebrew 安装、Agent 由 npm 安装时，Agent 仍按其 npm 全局包归属处理。

确认页显示“检查时可用版本”，更新器决定实际安装版本。成功判定要求命令正常退出、安装入口可验证、实际版本不低于原版本；命令成功但版本未变时明确说明，不声称安装了提示版本。确认升级前直接展示执行命令；确认后打开后台任务详情。任务显示当前阶段、耗时、命令和实时运行日志（stdout / stderr），结束后展示退出码和版本核对结果。stderr 也可能包含正常进度与提示，不单独标成错误；是否成功由任务结果判断。没有可靠的安装百分比时不显示估算百分比。输出通过任务轮询更新，每个流保留末尾 16 KiB，完成后的输出随本地任务记录保存；关闭详情不影响后台执行。原生升级能力检查与正式执行使用相同的明确 HOME，准备失败时在发起窗口显示失败步骤。

### 官方升级方式核对

- [Claude 官方更新文档](https://code.claude.com/docs/en/setup#update-manually)：普通原生更新用 `claude update`，`claude install <版本>` 是指定版本安装／重装；npm 和 Homebrew 安装分别使用包管理器。
- [Codex 官方 CLI 文档](https://learn.chatgpt.com/docs/codex/cli)：npm 用 `npm install -g @openai/codex`，Homebrew 用 `brew upgrade --cask codex`。官方独立安装脚本同样可更新，但 App 尚未接入该安装布局的升级，不会将独立二进制改用 npm 安装。
- [Gemini 官方安装与渠道文档](https://geminicli.com/docs/get-started/installation/)：npm 的 `@latest` 为稳定渠道，Homebrew 管理 `gemini-cli`；preview/nightly 不会在此入口被自动降级到稳定版。MacPorts 等尚未接入的安装方式不回退为 npm。
- [Grok 官方 CLI 参考](https://docs.x.ai/build/cli/reference)：`grok update` 沿用当前渠道，`--version` 是指定版本安装，`--alpha`／`--stable` 是主动切换渠道，普通升级不加这些参数。

本入口只更新已经验证归属的安装。未接入的独立安装脚本、包管理器或安装布局，应使用对应官方升级方式，不自动切换安装渠道。

## 从哪里进入

| 入口 | 用途 |
| --- | --- |
| 总览 | 查看各 Agent 的安装与版本，从卡片直接进入配置编辑、版本与路径、启动及资产分类。 |
| 共享库 | 集中查看已保存的共享资产，按类型切换，编辑定义或配置到 Agent。 |
| Skill / MCP / 插件 | 查看全局资产及各 Agent 的绑定、原生状态和配置差异；支持按 Agent、状态和来源筛选。 |
| Hook | 集中查看、收录、编辑和应用 Hook，管理各 Agent 绑定的启停与移除；会话集成是其中的辅助入口。 |
| 会话 | 在历史与活动视图间切换，按 Agent、工作目录和主子会话筛选，检索正文并继续原生会话。 |

点击卡片中的资产分类会筛选同一份全局列表。顶部的 **配置范围** 可选择 **全局与用户配置** 或一个工作目录；具体可读、可写范围以详情和操作计划为准。

总览卡片的资源数量与 Skill、MCP、插件、Hook 目录来自同一份后端盘点。进入 Agent 区域后读取一次当前配置范围，切换分类直接复用目录；来源变化或手动刷新时才重新盘点。较长的列表按可见区域渲染，滚动即可浏览全部结果，搜索与计数仍覆盖完整目录。切换分类会重置该分类的附加筛选，路径选项只列出当前分类与 Agent 对应的来源。

Agent 卡片与中转站卡片使用相同宽度，按窗口空间自动排列。顶部 Agent 标志使用无外框的原生图形；点击名称打开官方文档，悬停时显示下划线和提示，点击版本号进入版本与路径。Skill、MCP、插件、Hook、历史和活跃六项统计横向排成一行，标签在上、小字号数字在下并居中对齐；悬停可查看完整含义与数量，点击进入对应列表。配置区只展示已有文件，以紧凑的文件名标签全部列出，空间不足时自动换行，卡片随内容增高。

卡片的流动边框从已加载的 Agent 图标提取主色，并按图标来源缓存结果。黑白标志使用随明暗主题调整的单色；图标尚未加载或取色失败时使用已有品牌配色。

配置摘要显示文件名，同名文件用路径区分；悬停可查看完整路径和配置范围。点击标签直接进入编辑器，只读文件直接预览。**定位** 和 **系统打开** 位于编辑器或只读预览中，对应当前打开的文件。

底部保留刷新和 **启动**，刷新期间不能重复点击刷新。**启动** 位于右下方，确认未安装时显示 **安装说明**，直接打开对应 Agent 的官方安装指南。顶部版本号进入 **版本与路径**，查看本机已有安装、更新、启动路径、诊断和深度扫描；顶部 **未安装** 状态也可打开官方安装说明。后台任务通过顶部统一入口查看。数量未确认时显示 **—**。

重新打开 App 时，卡片先显示本地保存的版本与配置文件摘要；有资源目录缓存时先显示缓存，再核对当前来源。Agent 页面可见时每 30 秒检查已知来源、完整 Skill 包中的文件、目录和安装文件的变化，窗口重新显示时也会检查；检查本身只读取文件元数据，不重新解析正文或运行 CLI。已有内容在刷新期间保留。

资源列表可见后，打开内容、编辑原文、查看 Agent 使用详情、配置或启停、整理关系及收录或删除共享定义，都会先确认当前窗口的目录已就绪。正在读取时共用同一次读取；已经就绪时只做轻量确认，目录缺失或有变化时才恢复。读取失败可在当前操作中重试，恢复过程中可以关闭面板。此流程用于 Skill、MCP、插件及扩展和 Hook。

目录刷新保留当前面板、仍存在的资源选择及编辑草稿。目录变化会使已生成的配置、启停和关系整理预览失效，需重新预览后确认；原生操作面板也提供 **重新预览**。收录或删除时若发现来源或共享版本已变化，会要求核对后重新操作。切换页面或配置范围会关闭原操作面板，关闭后的旧读取结果不会重新打开它。

卡片的 **刷新** 会重新读取该 Agent 的版本与配置摘要，并刷新当前范围共用的资源目录；总览刷新同时更新全部 Agent 的摘要。安装、升级和保存配置完成后更新对应结果。版本管理在打开时加载，Hook 会话接入检查在展开辅助区时加载；摘要不再另行扫描资源或让目录反复过期。历史数量直接统计原生索引和会话身份元数据，进入总览、目录集合变化或手动刷新时更新；窗口重新显示且距上次读取超过 30 秒时也会更新。活跃会话继续实时更新。

历史数量包含主目录本身和已记录目录中的主、子会话，沿用历史列表的来源、范围和原生身份去重规则。Codex 读取 SQLite 会话索引，Claude 和 Gemini 只读取必要的身份元数据，Grok 读取原生摘要；统计不依赖标题、正文可读性或恢复能力。卡片显示完整统计的准确数字，首次读取显示 **统计中**；原生索引或身份元数据无法读取时显示 **读取失败**，悬停可查看原因。不会把列表的一次部分查询缓存为总数，也不使用 `≥` 或 `≈` 表示历史数量。无标题或正文不可用的原生会话仍保留其身份，能否继续由原生能力另行判断。

点击 **启动** 后，中转站选择器同时展示名称、协议、地址和账户身份；使用 API Key 的配置展示备注或脱敏标识，便于区分同名站点。密码、Token、Cookie 和 Key 不以明文展示。通过中转站启动时使用所选中转站的 Key；沿用本机配置继续会话时，如需登录，由 Agent CLI 自身引导。

## 查看和继续原生会话

顶部 **会话** 默认进入历史；卡片上的活动会话数字进入对应 Agent 的活动视图。历史与活动数量分别展示，无法确认活动状态的记录显示 **活动状态未知**。

历史默认查询 **主目录本身**。目录选择器复用临时 CLI 已记录的工作目录，也可以选择 **全部已记录目录（含主目录）**。这些目录内从终端或其他 App 创建的原生会话同样可见；主目录不会递归包含所有子项目，未记录的项目不会自动加入范围。已记录目录暂时不存在或外置盘未挂载时，只要原生存储仍可读，就能查看历史。

搜索可匹配标题、会话 ID 和用户、助手的对话正文；工具输出不混入普通正文搜索。通过 **全部会话 / 主会话 / 子 Agent 会话** 筛选，点开详情查看消息、复制 ID 或目录。已确认父关系的子会话可以跳转父会话；缺少证据时保留未知关系。记录较多时点击 **继续加载**，读取未完成或某个来源不可用会单独说明，已加载数量不代表完整历史总数。

历史列表使用与资产列表一致的卡片，按最后更新的本地日期分组，卡片右侧显示时分，悬停查看完整时间。点击标题打开详情，底部可直接复制完整目录和会话 ID；ID 不再占据一整行。详情将会话关系、模型、时间和活动状态集中在正文上方，目录与完整 ID 单独排列。临时 CLI 的历史选择列表复用同一组件。

**清除筛选** 会清空搜索和角色条件，保留当前 Agent 与工作目录范围。**来源读取情况** 可展开核对各来源；遇到未完整读取的来源时自动展开，可读结果继续保留。子会话通过 **查看父会话** 跳转，悬停可查看父会话的完整 ID。

详情中的搜索覆盖已读取的对话与执行活动，支持 Enter 查找下一条匹配消息、Shift+Enter 查找上一条；没有结果时显示 **未找到匹配**。搜索命中收起的执行活动时，会展开并定位到具体内容。收起的工具正文按需渲染，仍可随时手动展开或收起；已展示消息的时间与复制按钮不再需要悬停后才显示。内容读取不完整时会明确说明搜索范围。

点击 **继续会话** 后默认 **沿用 Agent 当前配置**，无需 BalanceHub 中转站；也可选择 **选择中转站继续**，临时使用指定配置恢复同一条原生会话。确认后弹窗关闭，启动结果进入后台任务。已有确切活动实例时，可在能够定位终端的情况下切回；重复提交同一原生会话不会自动重复启动。结果待确认时保留任务状态，不自动重放。

浏览历史不要求 CLI 仍安装。继续需要工作目录可用、CLI 与原生来源匹配，并满足该类会话的原生恢复能力。不能独立恢复或能力尚未验证的子会话仍可查看与搜索，界面说明原因；不会悄悄改成新建或继续父会话。工作台不改写、删除原始会话文件，Agent 在原生继续后的记录更新由 Agent 自身处理。

## 同一个资产与多个 Agent

全局列表以紧凑的横向卡片展示资产，沿用中转站和 Agent 卡片的材质、彩色高光和悬停效果。左侧突出资源名称与来源文字，Skill、MCP、插件和 Hook 使用蓝、绿、紫、金色分类图标；右侧以原生图标、名称和 **生效、已停用、未确认** 等状态展示 Agent 使用情况。已确认未配置的 Agent 不占位，未知、缺失和停用的来源仍保留。点击 Agent 状态打开使用面板，按实际配置位置查看状态和操作。长名称最多显示两行，悬停可看全名；名称与使用区按实际占用宽度排列，放不下时才换行。

点击资产行中的 Agent，在使用面板的具体配置下选择 **移除此配置**，预览删除差异与影响范围，确认后进入后台任务。使用面板和详情的「配置来源与管理」共用操作组件与后端状态结果：已启用时显示 **停用**，已停用时显示 **启用**；启停状态无法确定时保留状态说明与查看入口。由父插件控制时明确标为 **启用所属插件 / 停用所属插件**。面板顶部说明同步来源，内容一致显示 **已同步**，有差异时按来源提供 **应用共享版本** 或 **同步来源内容**，未配置时提供 **配置到此处**；内容尚未完整核对时不会显示成已同步。内容比对和目标可用性复用配置选择页的后端结果，不额外扫描资源。**移除此配置** 放在每个具体配置下方的次要操作区；不能执行的原因保留并去重。**查看来源** 会展开详情中的配置来源并定位到所选位置，**打开详情** 则从共同正文开始阅读。

Skill、MCP、插件 / 扩展和 Hook 共用排序入口，默认按名称正序，也可选择名称倒序、创建时间或修改时间的新旧顺序。时间来自扫描时读取的实际来源文件元数据；多来源取最早创建和最近修改时间，共用配置文件的条目具有相同时间。没有来源文件时间的条目始终排在末尾，不以扫描时间代替。按时间排序时，每行会展示对应时间，排序控件旁可查看时间取值说明。通过其他页面跳转到某项资源时会滚动定位，不改变排序。筛选无结果时，可从空列表中的 **清除列表筛选** 恢复当前搜索与 Agent 范围下的结果。

同一 Agent 可从不同路径引用同一个资源。例如用户 Skill 目录中的链接与共享 Skill 目录可能指向同一份文件。多处状态相同时直接显示状态与数量；不同状态并存时显示 **N 处配置**，悬停和使用面板列出各处的启用、停用、被覆盖等状态，不把正常的来源优先级称为配置冲突。卡片右侧 **配置到…** 用于选择 Agent 和范围，在预览后写入配置。来源尚未确认时显示 **未确认**；已有记录但当前缺失的配置仍显示 **缺失**，便于处理。

**扫描说明** 分别说明安装位置扫描、资源读取和运行时状态，静态配置已读取不代表已观测到 Agent 的实际加载结果。安装发现只把实际存在的自动候选程序计入限额，缺失的用户指定路径仍会报告诊断。Gemini 内置 Skill 按已核验的 npm 包身份及 `bundle/builtin` 布局识别，不因版本号变化直接停止发现。

资源名称下方直接展示 **插件提供、本地文件、共享目录、链接引用** 等已知来源信息，存在配置差异时以醒目的文字标出。点击来源文字可展开对应 Agent、范围和路径。详情保留完整来源特性及各自图标，作者只在具备明确来源证据时展示。列表只使用已有盘点信息，不为展示卡片额外读取资源正文。

点击资源名称，详情会立即读取实际内容，在同一处查看和编辑：

- **Skill**：直接阅读完整 `SKILL.md` 正文。
- **MCP**：按连接字段展示所选服务，默认通过表单编辑，也可切换原生 JSON/TOML；编辑后只更新对应条目。
- **插件 / 扩展**：展示描述、版本、定义文件和已有 README；点击包含的 Skill、MCP 或 Hook，可继续查看其内容，并返回所属插件。
- **Hook**：展示触发事件、匹配条件和实际执行配置，不会执行其中的命令。

Skill、MCP、插件 / 扩展和 Hook 共用同一套内容详情，不再先选择 Agent。相同内容合并展示，有差异时在同一页面直接展示带行号、增删标记的对比；相同上下文可展开。正文顶部简要列出 Agent 与来源数量，展开 **来源路径** 可查看每处的范围和实际路径。默认以完整的共享定义为对照，没有共享定义时先展示读到的完整内容，随后补齐其他来源和差异，保持正在阅读的正文稳定。JSON、JSONC、TOML 等原生格式会明确标注，保留各自的实际原文。

重新打开最近读过的资源时，先显示当前窗口的内存缓存，同时核对文件变化；刷新期间保留正文，失败时明确标记尚未核对成功。缓存有数量和体积上限，不写入磁盘。每项资源单独判断内容版本，无关资源变化不会触发当前正文重读。

目录按来源解析 MCP 配置、枚举 Hook 规则；相同物理 Skill 包只完整读取一次，包含资源文件和执行权限的比较规则保持不变。

打开 **配置到…** 或 Agent 使用面板时，复用列表已完成的盘点和操作能力，不重新扫描全部 Agent，也不提前为每个候选位置生成修改方案。Skill、MCP 和 Hook 共用按 Agent 展示的选择列表，区分已配置、内容不同、未配置和待核对；用户、项目及项目本地范围分别选择。Skill 比较完整资源包，MCP 比较完整连接定义；这些状态复用已有比较指纹。共享库中的相关元数据一次读取，不为候选列表复制历史版本内容。完整目标路径在更改预览中展示。

Skill 的配置入口按 Agent 已支持的原生目录、平台文件写入能力和项目信任状态判断，不要求当前 CLI 的完整版本号出现在验收名单中。Agent 的普通版本升级不会因此禁用 Skill 分发。已有相同内容显示 **已配置**；不可配置的位置直接说明原因。写入前仍会检查实际权限、符号链接、资源归属及同名目录，保留预览和确认步骤。

MCP 也不以完整 CLI 版本名单控制配置入口。后端先将各 Agent 的配置解析为统一连接定义，再按目标格式写入；检查传输协议、工作目录以及实际认证/运行环境依赖是否有等价配置。预览再读取当前配置，验证文件结构、重复字段、权限和同名资源归属。启用状态、超时、工具策略及其他本地配置保留；普通 MCP 不因附带这些字段而被限制为只能配置到原 Agent。真正没有等价写法的认证或运行环境依赖会列出具体字段。同名但未关联的不同连接定义需要先核对并关联来源，不能直接覆盖。

选择目标后，预览只补查所选 Agent、资源及可能受影响的共享来源，再生成实际文件差异或原生操作计划。共用物理目录的 Agent 和父插件影响范围会一并核对。候选可选只表示具备配置入口，最终是否可执行以预览中的当前权限、版本、归属和文件检查为准；确认提交前仍会重新校验。插件 / 扩展的原生启停也按相关 Agent 范围准备。

关闭配置预览、切换目标或读取超时会取消旧预览请求，后到结果不回写，忙碌状态会释放；正在进行的单次系统读取或原生探测在其原有时限内结束。打开选择界面不会收录或保存共享定义，确认执行后才进入后台任务。

正文、Agent 使用面板和原文编辑复用列表已完成的盘点，只读取选中资源需要的文件；相同物理文件的原文和解析结果在一次正文读取中复用，来源发生变化时才补查相应 Agent。慢来源的补查放在其他可读来源之后。关闭、切换或读取超时会取消旧请求，后到结果不回写；文件编辑和实际保存仍核对当前原文与写入权限。

Skill 比较完整 `SKILL.md`；MCP 比较所选服务的配置；Hook 同时比较触发事件、执行配置及匹配条件等全部规则字段；插件按说明文档和定义文件分别显示差异，内容相同的 README 不重复展示。插件包含的资源和父插件入口也会归并，保留跳转。附带文件、执行权限等完整资源包差异仍在资源管理中查看。

点击 **编辑原文** 时，只有一个可写文件就直接打开编辑器；存在多个目标时平铺文件名、使用来源和路径，点击文件即可编辑。共用同一文件和条目的 Agent 归为一个编辑目标。保存只作用于明确选中的目标，保存前仍需预览文件差异，确认后进入后台任务。返回内容会保留当前原生编辑草稿。只读内容仍可阅读和复制；未完整读取的来源会说明原因，不视为相同，也不把未读到的文件当作新增或删除。无法独立提取的配置会明确说明并展示完整来源文件。

**配置来源与管理** 默认折叠，集中放置路径、来源证据、启停、移除、收录共享库及关系整理。从使用面板点击 **查看来源** 时会自动展开并定位，信任等诊断信息放在对应来源的 **来源与诊断** 中。正文查看不再经过配置预览和原生详情两层入口。

共用同一份原生配置的来源会显示在同一行。独立副本中，Skill 和 MCP 在同类别、同名且完整内容相同时自动归并；Skill 比较包括资源文件和执行权限，MCP 比较协议、命令/参数、URL、工作目录、环境变量、请求头及实际认证/运行环境依赖；JSON/TOML、type/transport、url/httpUrl 和 headers/http_headers 的等价写法不构成差异。启停、超时、工具列表、信任和说明等本地策略不影响同一连接的归并，也不阻止分发。Hook 按完整规则归并，事件同名或执行名称相同都不足以证明内容一致。归并保留各 Agent 的配置与状态，不会改写原生内容；已有的独立共享版本历史、恢复记录和明确保留分开的决定也会保留。归并后某一份被手动修改，会在同一资产的详情中展示内容差异。

例如，只有 Codex 配置的 Skill，可点击 **配置到…** 并选择 Claude，完整资源文件会一并分发。同一个 Agent 有用户、项目等多个范围时，先选择本次要操作的范围；每次写入均需预览确认。已有但停用或状态未知的绑定仍按实际状态展示；按 Agent 筛选只改变可见的使用状态，其他 Agent 的配置和状态保持原样。不同内容或多个独立版本历史需要先在详情中明确选择来源或整理关系。

状态无法判断时，使用面板会说明原因并提供相应查看入口。文件无法读取、格式解析失败、证据不完整和原生能力限制分别处理；不能把“未知”理解为一定没安装或一定不能使用。插件提供的资源不能独立控制时，可前往所属插件查看。

插件页同时汇总原生 Plugin / Extension。可用的详情与启停动作取决于对应生态；插件安装仍按各 Agent 的原生方式进行。工作台不把不同生态的插件转换成一个可跨 Agent 安装的共享包。

插件主行只展示实际关联的 Agent，不会因为其他 Agent 缺少通用安装目标就显示“未确认”。**已启用** 表示本地安装与配置证据支持启用状态，不代表已验证某个运行中的会话加载成功。已有插件的状态无法完整判断时显示 **状态待核对**，悬停和使用详情提供已知原因；同名插件是否跨生态兼容需另行确认。

### 从 Agent 移除配置

- **Skill**：可移除原生技能目录中的独立资源；预览包含包内文件的删除差异。指向共享 Skill 的目录链接只解除该链接，保留共享源。直接删除共享目录中的资源会影响读取它的 Agent，预览展开受影响的来源入口。多个 Agent 共用同一路径时只执行一次删除。
- **MCP**：删除选中作用域的服务声明，保留同文件的其他服务、设置与注释。Claude 项目本地配置按对应工作目录定位；JSON、JSONC 和 TOML 使用各 Agent 已有的文档解析器。
- **Hook**：移除选中的原生规则；停用后保留的恢复配置也可移除。
- **插件 / 扩展及插件附带资源**：插件卸载仍需使用所属 Agent 的原生入口，不能以删除其中一个 Skill 或 MCP 文件代替卸载。系统内置资源、不可写来源及无法完整读取的资源会说明具体限制。

移除原生配置不会删除共享库中的定义，也不会因打开移除面板而自动收录资产。确认前与提交前均核对来源、内容和影响范围；外部修改会使预览失效。Skill 只删除已预览的文件和空目录，不递归删除操作期间新出现的内容。多个文件不承诺原子成功，失败或取消后会报告未完成状态，不能假定所有更改已回滚。当前文件移除执行器支持 macOS / Linux，Windows 显示平台限制。

### 哪些资源可以共享

| 资源 | 原生共享方式 | BalanceHub 当前处理 |
| --- | --- | --- |
| Skill | 部分 Agent 识别用户或项目的 `.agents/skills`，同一目录可以被多个 Agent 发现；其他 Agent 使用各自的技能目录。 | 识别同一物理来源，共享目标只列一次，并显示发现它的 Agent；也可分发为独立副本。 |
| MCP | 多个 Agent 可以连接同一个远程 MCP 服务；连接声明、认证和本地启停策略通常保存在各 Agent 的原生配置中，没有本应用所支持四种 Agent 都默认读取的统一 MCP 目录。 | 共享库保存可复用定义，按目标格式写入配置。原生配置并非持续同步；更新定义后需预览并应用。stdio 通常由各 Agent 分别启动进程。 |
| AGENTS.md 等项目指令 | 支持相同文件的 Agent 可以读取同一份项目指令；文件名、加载顺序、覆盖与导入规则由各 Agent 决定。Gemini 可通过 `context.fileName` 指定文件名，Claude 的 AGENTS.md 兼容读取有原生版本与功能条件。 | 在 Agent 卡片的配置文件入口发现和编辑已有指令文件；目前没有指令文件的共享库分发功能。发现文件不等于确认当前会话已加载。 |
| Hook | 不同 Agent 的事件、匹配条件和执行格式有差异，不能默认共用一份原生 Hook 配置。 | 共享库维护各 Agent 的原生变体，按目标分别应用。 |
| 插件 / 扩展 | 同一项目可以提供多个生态的包，但安装注册和加载机制需要分别适配。 | 展示实际安装关联与原生操作，不推断整个插件包可跨 Agent 通用。 |

这里的 **全局／用户配置** 指对某个 Agent 的多个项目生效，和 **多个 Agent 共用** 是不同范围。`AGENTS.md` 是常见指令文件名；任意命名的 `agent.md` 不会自动获得相同加载规则。

MCP 详情与资源归并共用规范化的连接字段：相同连接合并展示来源，仅连接内容不同才展示差异；未能解析的来源单独说明。“编辑原文”仍打开各 Agent 的真实 JSON/TOML 条目，保存预览显示实际文件更改。

新增 MCP、编辑共享定义和编辑原生 MCP 单条连接，默认使用同一中文表单：

- **远程服务**：填写服务商提供的完整 MCP 地址，保留路径和查询参数。默认使用 Streamable HTTP，服务明确要求时才展开传输方式改选 SSE 或 WebSocket。
- **认证**：选择无需预填凭据、访问令牌、请求头或 OAuth 参数。访问令牌可直接填写或引用环境变量名；自定义请求头逐行填写名称和值。OAuth 区域仅配置服务要求的客户端和权限参数，网页登录仍由 Agent 完成。现有混合认证使用组合配置，补充请求头、动态命令等按需展开。
- **本地程序**：填写启动命令、逐项参数；需要密钥、特定目录或继承变量时，再展开运行设置。远程认证字段不会混入本地启动表单。

字段的适用连接方式与 Agent 支持范围由后端适配器提供。编辑某个 Agent 时，只提供它支持的常规字段；共享定义中有限定范围的字段标明可用 Agent。已有的专属或复杂字段在“已保留的其他字段”中单独列出，切换认证方式不会自动删除这些保留项，可明确从草稿移除。字段格式、必填项及令牌来源冲突会提示；提交时定位有错误的表单项。连接语义和最终配置仍由后端现有校验处理。

“编辑原文（高级）”用于直接编辑 JSON 或原生 TOML。表单不完整时也能切换，界面明确说明原文仅包含最后一次有效内容；可返回继续填写，或明确以原文为准。没有改动原文时，返回表单保留未填完的内容；改动原文后只有解析成功才替换表单。切换连接方式或认证方式保留输入草稿，保存使用当前启用的字段。

原生 MCP 编辑的表单草稿与文本草稿一起暂存内存，关闭并重新打开同一资源可继续，退出 App 后不保留。所有编辑入口复用后端校验和适配器；原生启停、超时、工具策略及其他本地字段保留。打开或切换视图只转换内存草稿，不写文件、不启动 MCP、不刷新资产目录；转换有超时及过期结果保护。确认写入前继续使用 diff 预览。

原文中的 `type` 仍可省略，由后端根据命令、地址及来源 Agent 的规则识别。表单负责提供连接方式选择，普通用户无需记忆字段名或编写 JSON。

MCP 的 stdio、Streamable HTTP、旧版 SSE 和 WebSocket 按目标 Agent 的官方配置能力转换；OAuth 常见字段、动态请求头与环境变量引用按连接含义比较。具体支持矩阵、不能等价转换的情况及文档依据见 [MCP 配置覆盖范围](agent-mcp-configuration.html)。

## 区分内置、插件附带与独立资源

Skill 就是技能，两者是同一类别。列表中的 **提供方式** 区分 Agent 自带、插件提供和独立配置；插件附带的 Skill、MCP 和 Hook 保留父插件关系，管理入口会说明由哪一层控制。

展开 **筛选条件**，可以进一步选择提供方式、安装来源、配置范围和来源路径；收起后，已选条件仍以可单独清除的标签显示：

- **安装来源**：随 Agent 内置、原生扩展包、本地文件、共享目录、链接引用或配置文件注册。
- **配置范围**：反映该绑定在用户、项目、系统等哪个范围生效。同一资产的不同 Agent 绑定可以有不同来源和范围。

共享目录及其链接引用会按实际物理来源归到同一全局资产。组合筛选匹配同一个 Agent 绑定的来源，避免把不同绑定的信息拼成不存在的结果。

同一 Agent 配置环境中，独立 Skill 的多个入口若经后端核验指向同一物理来源，会合并为一份使用状态。例如 `.grok/skills` 中的链接指向 `.agents/skills` 时，列表显示 **已启用**，使用面板说明 **共享 Skill，通过 Agent 目录链接引用**。使用面板直接保留全部路径、原生优先级状态及各入口操作；不把同源的未采用入口算成第二份安装。独立副本、不同配置环境或物理来源无法核验时不做这种归并，状态证据冲突时仍显示待核对。

MCP、Hook、插件、扩展和状态栏配置使用同一套入口归并：只有同一 Agent、配置环境、作用范围和插件归属下，已核验为同一物理来源的同一条原生定义才合并展示。同一文件中的不同 MCP 服务、Hook 规则或插件注册仍分别保留；命令、地址或内容相同不代表是同一份配置。配置面板复用该结果，从已确认同源的入口中选择一个可写位置，再由预览核对实际路径与影响范围。插件附带资源保留父插件的操作规则。

部分 Agent 的默认技能列表会隐藏内置技能，统一盘点会单独标识。安装包无法核验、版本尚未适配或运行期加载状态无法确认时，界面保留相应盘点说明；原生内置工具和斜杠命令不会自动被当成 MCP。

## 跨 Agent 安装与版本管理

Skill、MCP 和 Hook 可以维护共享定义。它保存一份可编辑的内容，各 Agent 绑定则记录实际配置和已应用版本。

从 **Agent → 共享库** 查看所有已保存的共享资产，使用 **全部 / Skill / MCP / Hook** 切换类型，也可搜索名称和摘要。列表显示共享版本及各 Agent 的配置状态，可直接 **编辑定义** 或 **配置到…**。进入共享库会清除之前的 Agent 筛选，未配置到任何 Agent 的定义也会显示；顶部配置范围用于查看该范围内的 Agent 使用情况。

已有资产选择 **保存到共享库** 后，仍可在原分类中查看；详情顶部新增 **在共享库中查看**，点击会进入共享库并定位该资产。共享库为空时可使用 **新建共享资产**，或者从原生资产详情收录。这里只管理 BalanceHub 保存的共享定义，Skill 的原生共享目录仍显示在来源信息中。

将现有资产配置到另一个 Agent 时，点击该 Agent 的状态并选择 **配置到此处**。内容明确且完整可读时，工作台直接准备计划，无需先手动收录；最终确认后才保存所需共享定义并写入目标配置。取消预览不会创建共享版本。存在不同内容变体时，先在详情中选定来源。配置完成只表示定义已写入，是否启用、受信任仍以 Agent 的原生状态为准。

配置 Skill、MCP 或 Hook 时，同一范围内每个 Agent 只展示一行（多个独立配置环境会分别标明）：完整内容一致显示 **已配置**，不再提供重复安装选项；内容不同则标明 **内容不同**，在原位置可安全写入时提供更新；尚未配置则使用该 Agent 的默认原生位置。Skill 比较完整包及执行权限，MCP 比较完整连接配置，Hook 比较对应 Agent 的事件、匹配条件和完整规则；已有规则保留原位置。多个范围通过范围按钮切换，无需逐个选择目录。每个范围显示已选数量，切换后保留选择；只有一个范围时也会明确标注范围名称，预览逐项标明写入范围。

Agent 安装包内置的 Skill 也参与已有配置判断：当前范围没有独立副本时，核对同一 Agent 配置环境的内置来源。完整内容一致会显示 **已配置** 并注明 **Agent 内置提供**；不同或无法完整核对时显示对应说明，不把“没有用户目录副本”当成“此 Agent 未配置”。已有用户或项目副本仍按该范围的实际内容比较。

共享目录单独列为 **共享配置**，同一个位置只出现一次，并说明哪些 Agent 会发现它。已有共享来源不会自动复制到独立目录；无法确认内容、存在多个配置环境或同名副本时，会提示先核对来源。缺少写权限、项目尚未信任或原生格式无法安全处理时，相关操作会说明具体原因。CLI 版本不在历史验收记录中，不会单独导致禁止配置。

配置选择也复用同源核验结果：共享目录及其链接指向同一份 Skill 时，Agent 行注明 **使用共享 Skill**，不会提示多份同名配置。内容不同时可通过 **查看共享配置** 定位唯一的共享更新选项，预览后再确认；完整内容无法核对或属于独立同名资源时仍保留原因和比较入口。操作预览按 **来源入口** 展示影响数量与路径，共享文件更新可能影响多个入口。

配置、启停和移除共用同一套操作预览：选定 Agent 或在详情中明确指定位置后，核对目标路径、逐行增删差异与受影响的资源。已选项目会高亮并显示数量，确认后操作进入后台任务；调整选择后需要重新预览。配置完成不代表资源已经启用或受信任。

需要新建、编辑或集中更新版本时：

1. 在相应分类点击 **新建 Skill / MCP / Hook**，或者在已有原生绑定中选择 **保存到共享库**。新建类型由入口确定，表单不再重复选择类型；共享库的 **新建共享资产** 菜单先选择类型，再打开对应表单。
2. 编辑内容后，选择 **保存到共享库** 或 **配置到 Agent…**。前者立即更新共享库，不改 Agent 配置；后者先进入范围选择，最终确认前不保存新版本。通过编辑表单进入配置预览时，可用 **返回编辑** 继续修改；关闭预览也会返回原草稿。保存过程中提交内容暂时只读，窗口仍可关闭；已提交的保存不会因此取消。
3. 选择需要新增或更新的 Agent，然后 **预览更改**；共享目录需单独选择。已有共享版本也可单独从 **应用到 Agent** 进入此流程。从详情指定位置的操作保留该目标；Hook 缺少对应 Agent 原生定义时，会提示先在编辑器中补充。
4. 核对目标路径、变更内容和影响范围，点击 **确认应用**。
5. 在 **Agent 后台任务** 中分别查看共享版本的保存结果和各目标的执行、验证结果。部分目标失败时，逐项处理原因，不把整批视为成功。

取消未确认的安装或保存应用预览不会新增共享版本，也不会改写原生目标。已经明确执行的 **保存到共享库** 是独立操作，不随之后取消安装而撤销。确认后若共享版本已保存、某些 Agent 应用失败，该版本会保留，后台展示各自结果。提交超时表示结果尚待核对，可刷新任务状态；不会自动重复写入。

名称和内容均未变化时，保存、收录及配置到 Agent 都复用当前版本。发生变化时递增版本，保留最近 32 个版本；仍被 Agent 应用或恢复记录引用的旧版本会额外保留，不再因累计 32 次保存而拒绝更新。

没有原生关联、Agent 应用或恢复记录、手动合并关系的共享定义，可在详情底部选择 **从共享库删除**。确认后删除这份定义及其版本记录；不会操作原生文件。目录或版本发生变化、相关后台任务尚未结束时会拒绝删除，需刷新后核对。

共享定义更新后，已有绑定会提示 **共享定义有新版**；手工改过原生配置时会提示 **原生配置已修改**。你可以先查看差异，再决定是否应用。缺失、未知和配置冲突会保留相应提示。

详情展开「配置来源与管理」时，从已发布的资产快照读取操作，不触发全量扫描；读取中仍可关闭详情、查看原生配置。批量操作只汇总当前可执行、方向相同的配置，按钮标明数量，并携带明确的目标列表进入预览；可在预览中调整目标。批量移除与单项移除都放在次要操作区。只有一个可操作目标时，直接使用对应配置上的按钮。来源列表默认显示 Agent、范围、状态、配置路径和可用操作。插件提供的资源直接给出“管理所属插件”，不可执行操作的原因、内容比对状态、信任信息和来源证据收在“来源详情”中；顶部不再重复显示配置份数、图标标签和同一限制说明。目标不支持原生开关、缺少完整来源、没有写入权限或当前平台没有所需文件操作能力时，可展开详情查看具体原因。MCP、Skill、插件及扩展启停按实际原生配置、归属、信任和已安装状态判断，不再使用 CLI 精确版本、安装渠道或历史验收记录作为操作白名单。执行前仍核对文件与可执行程序是否变化，执行后重新读取状态；原生命令失败或结果无法确认时会如实报告。

## 内容比较

资产详情、编辑器和操作面板的信息组织遵循 [界面信息层级](./ui-information-hierarchy.md)：默认显示对象、状态和操作，来源证据及一般说明按需展开，修改前的差异与影响范围保持可见。

配置文件与资源原文共用代码编辑器：提供行号、语法高亮、当前行提示、查找与替换、自动换行和光标位置；支持 JSON / JSONC、TOML、ENV、Markdown 等格式。使用 `⌘F` / `Ctrl+F` 在文件内查找；只读内容提供查找。切换 **内容 / 差异** 保留光标及撤销记录，格式化仍只修改草稿，可撤销。

文件编辑与只读预览窗口默认使用更大的工作区，右上角可最大化或还原。编辑区使用清晰的边框、独立背景和浅色 / 深色语法配色；原生文件编辑区随窗口伸展，底部保存操作保持可见。资源详情进入编辑时自动加宽，也可手动展开面板。

App 中的内容比较统一使用逐行 diff，显示红色删除、绿色新增、两侧行号，并支持展开相同上下文：

| 入口 | 比较内容 |
| --- | --- |
| 原生配置、资源原文编辑 | 原始文件与当前草稿 |
| 配置保存预览、CLI Key 切换 | 当前配置与即将写入的配置 |
| 原生资产启停、移除 | 变更前后实际内容 |
| Skill、MCP、Hook 配置到 Agent | 各目标的原内容与待写入内容 |
| Skill、MCP、Hook、插件及扩展的来源差异 | 文件、说明及属性变化 |
| 同名资源比较 | 所选两处来源的文件与权限变化 |
| 共享定义的 **查看修改差异** | 名称、MCP 字段、Skill 原文、Hook 事件与规则，以及变体增删 |
| Hook 会话接入的安装、启停、删除 | 原生配置文件与接入状态的变化 |

Hook 会话接入预览与写入共用同一份配置生成逻辑，确认时重新核对原文和预览；原生文件变化后需要重新预览。未读全、截断或二进制内容会保留原因，不把缺少正文视作删除。

## 整理同名资源

列表中的 Agent 状态只来自实际绑定或已有应用记录。同名但独立的资源不会成为另一条资源的“状态待核对”Agent；名称相同不代表内容一致，也不要求合并。

存在其他同名资源时，列表显示 **另有 N 份同名资源**。点击后在详情中展开对应资源、所属 Agent 和来源数量，可 **查看资源** 或 **比较内容**。配置已有资源到其他 Agent 时，目标已有另一份同名内容会明确说明，并提供 **查看并比较同名资源**；打开比较保留原配置选择，不自动替换或合并。未保存草稿不使用已保存资源的比较结果冒充草稿比较。

**比较内容** 使用与配置编辑器相同的逐行 diff：红色删除、绿色新增，显示两侧行号；变化文件默认展开，相同文件和相同行可按需展开。Skill 同时比较 `SKILL.md` 及附带文本文件，并单独标明执行权限变化；MCP 按统一连接字段显示 JSON 差异，等价的原生格式不算修改；Hook 同时展示触发事件和完整规则的变化。多来源资源可分别切换左右比较来源，当前来源的逐行差异不会替代完整资源的比较结论。二进制、未读全或截断的内容会说明限制，不把未展示的部分视作删除。各 Agent、范围、路径和原文在 **来源详情与原文** 中查看。

资产详情底部的 **整理资源关系** 默认折叠，保留已分开的记录和手动合并关系。进入比较后，可以根据内容差异决定是否属于同一资源：

- **合并展示**：先选择归入哪一项并确认。保留双方原生配置与内容差异，不会把其中一份覆盖到另一 Agent。
- **关闭比较**：退出比较，不保存整理决定；**不再提醒** 在预览并确认后持久保存分开的决定，隐藏这对同名提示。之后可以恢复提示。
- **解除关联**：对于有记录且仍能安全拆分的手工合并，可以解除；程序按当前归属处理，不恢复旧文件或覆盖之后的原生修改。

对独立配置选择 **不再提醒** 后，会记住保持分开的决定，即使后续内容相同也不会自动归并。**恢复提示** 重新显示比较入口；需要再次确认合并，才会将它们整理到同一项。

同一物理文件、两份独立共享版本历史、正在执行的操作或无法核对的 Hook 恢复记录，可能限制合并或解除。比较页会给出原因，确认时再次核对。整理关系不等于卸载资源，也不承诺撤销关联之后发生的安装、编辑或原生删除。

## 更新已有安装

1. 点击 Agent 卡片的版本号或版本状态，打开 **版本与路径**，按需点击 **检查更新**。
2. 在 **本机安装** 中选择具体安装，点击 **升级**，核对目标版本、原安装目录和执行命令。
3. 确认后窗口立即关闭，操作进入 **后台任务**。期间可以继续使用主界面；写入开始前可取消。
4. 升级完成后核对实际版本。如需切换启动入口，可在结果中 **采用为启动路径**。

升级沿用该安装的原渠道和目录，保留已保存的启动路径与系统 PATH。来源、平台或依赖不满足条件时，界面给出具体原因，可按官方说明使用原安装方式更新。

未安装时点击卡片上的 **安装说明**，按官方指南自行安装，再回到 BalanceHub 刷新。BalanceHub 不提供独立 npm 安装，也不在应用目录下创建 Agent CLI 副本。

## 管理各 Agent 的 Hook

从卡片中的 **Hook** 或顶部同名分类进入同一份全局资产列表。用户自己配置的 Hook 可以直接收录到共享库，再编辑内容、保存版本并选择应用目标；无需先安装 BalanceHub 会话集成。

Hook 沿用同一套资源卡片，名称和 Agent 使用状态位于主行，触发事件、匹配条件和来源位于下方。事件与对应的匹配条件成对展示，仅相同的组合合并显示。规则优先展示自身名称；没有名称时展示命令、脚本或 MCP 工具名，完整执行内容可在详情中阅读。插件提供的规则会显示实际插件名称，点击来源可查看所属插件。

触发事件、匹配条件、执行配置和其他规则字段全部一致时，多个来源归为一行，正文只显示一次；有差异则在正文中直接对比。来源和原生绑定仍分别保留，编辑、启停和保存预览会标明本次操作的插件或配置来源。

列表顶栏分别显示归并后的规则数与来源数，同一规则可能有多个来源。同一 Agent 有多个来源时，在使用面板中分别查看和操作。触发事件和来源按可用宽度换行。

不同 Agent 的事件名称和配置格式可能不同。Hook 编辑器为各 Agent 分别保存原生变体，包括事件和一条规则的匹配组配置；只有具备对应变体且通过原生能力检查的目标才可应用。保存版本不会自动把一种 Agent 的事件转换成另一种格式。Hook 配置、原生启停及暂停恢复均校验实际格式和来源，不要求 CLI 命中历史验收版本。

在资产详情中选择绑定，已启用的配置提供 **停用**，已停用的配置提供 **启用**；**移除此配置** 位于下方次要操作区。计划会列出实际配置路径和受影响的其他规则，确认后进入后台任务。移除一个绑定保留其他 Agent 的配置和共享定义。

停用优先使用 Agent 原生开关。对于没有对应持久开关的规则，工作台先保存恢复副本，再从原生配置移出选定规则，详情显示 **已停用，定义已保留**。重新打开应用后仍可选择 **启用** 来恢复；给这种绑定应用新版本只更新保留的内容，仍保持停用。原生文件出现冲突或无法确认恢复位置时，会要求重新核对，不会覆盖邻近规则。

卡片数量是可确认的原生已配置规则数。一个文件可以有多条规则，多个 CLI 安装共用配置不会重复计数；禁用或待信任但仍保留在原生配置中的规则也计入。已移出原生配置的暂停规则在资产详情中保留恢复入口，不虚增原生数量。不可读、格式不支持或盘点截断时，保留未知数量和具体说明。盘点和编辑预览不会执行 Hook 命令。

页面下方的 **BalanceHub 会话状态接入** 可展开，检查、安装、启停或移除用于会话状态展示的回调。该入口始终操作用户级配置，并显示实际路径。它与普通 Hook 使用各自的来源和操作权限；系统托管、插件附带的 Hook 不会被当成 BalanceHub 所有。通过全局管理明确修改会话集成拥有的规则时，计划会说明影响；完成后专用集成不会自动修复并覆盖该自定义内容。

## 版本检查

卡片展示当前使用安装的 **已是最新 / 有更新 / 未检查 / 检查失败** 等状态。机器上有多份安装时，其他安装的更新不会改变卡片提示；各安装的状态可在 **版本与路径** 中分别查看。

进入 Agent 总览后，会在页面可见时自动检查版本。成功结果在本次应用运行期间缓存 6 小时；重新打开窗口或重新检测本机安装都会保留结果，并按当前本机版本重新比较。到期后后台再查，失败从 30 秒开始逐步延长重试间隔，最长 30 分钟。**检查更新** 会跳过本地缓存和失败等待，重新请求对应渠道；同时进行的同源请求会合并。

详情会显示最近检查时间。网络失败时标明 **检查失败**，保留上次成功版本和时间，不会把旧结果当作本次成功。版本来源未确认的安装显示 **暂不支持检查**。检查版本不会触发升级；原生渠道使用已确认的官方发布渠道，npm 安装使用 npm 最新稳定版。

## 版本与路径

点击 Agent 卡片顶部版本号，打开 **版本与路径**：

- **启动路径**：填写可执行文件并 **保存路径**；留空时自动发现。
- **本机安装**：只列出已有安装的版本、路径与当前使用状态；可 **采用此安装**、检查更新或预览原渠道升级。
- **诊断详情**：在对应安装下展开诊断，查看发现方式、版本来源和会话 Hook 状态；需要修改 Hook 时进入工作台的 **Hook** 分类。
- **没有找到安装？**：按需深度扫描其他安装位置，找到后 **采用路径**。关闭版本与路径或切换 Agent 会取消扫描。

底部的 **官方安装说明** 打开该 Agent 的官方指南。确认升级后，弹窗立即关闭，执行过程和结果进入后台任务。原生配置直接从卡片文件名进入，不再与安装信息混在独立环境面板中。全局设置继续用于代理、通知、自动刷新、自动签到和测活参数；测活的具体配置见 [测活配置](liveness.html)。

卡片展示全部已有文件。`AGENTS.md` 等指令文件是可选来源，缺失不代表配置不完整，卡片不提供通用新建入口。中转站默认 CLI 配置流程需要创建缺失文件时，会在编辑与保存预览中展示文件路径和内容，确认保存后才写入。

完整路径显示在编辑器中，**定位** 和 **系统打开** 就近放在文件旁；只读预览也提供这两个操作。配置读取异常及重试直接显示在卡片中，不可访问的文件注明原因。配置范围可在卡片文件的悬停提示中查看；Agent 实际使用哪些配置由其原生加载规则决定。Codex 的常用文件是 `config.toml` 和 `auth.json`。

保存配置时：

1. 点击卡片上的文件名，直接进入完整原文编辑。
2. 直接修改配置内容，包括其中的 Key 和 Token；可随时复制当前草稿、查看差异，或点击 **格式化** 整理 JSON、JSONC、TOML、ENV 和 Markdown。格式化不会自动保存。
3. 点击 **预览更改**，核对实际差异、目标路径、创建范围及重新加载提示，再点击 **确认保存**。
4. 确认保存后弹窗关闭，在后台任务查看逐文件结果。外部修改导致冲突时，先核对草稿，再重新读取当前来源；读取失败会保留原草稿。

未保存时关闭编辑器，草稿暂存在内存中；再次点击同一文件即可继续。切换到其他文件时，在编辑器内选择继续编辑当前草稿，或放弃草稿后打开新文件。草稿不会写入磁盘，退出 App 后不保留。编辑会话过期时仍可复制草稿，但需要重新读取文件后才能保存。

可以直接修改文件中的 Hook、MCP 和其他配置内容，保存时检查基本语法及外部变更。认证、系统或管理员配置不会仅因分类被设为只读；当前用户确实没有文件或所在目录的写入权限时，界面显示只读原因。多文件操作发生部分失败时按实际文件分别报告，不自动覆盖回旧版本或重复写入。中转站卡片中的默认 CLI 配置切换也使用同一个保存计划与后台结果流程。

**打开文件** 与 **在文件夹中显示** 由系统应用处理，按界面提示进入对应位置。原生配置管理中的预览、编辑、复制和差异均使用文件原文。MCP、Skill、Hook 及插件的资源详情直接读取实际内容；独立编辑条目或展示完整文件时，均以详情和保存预览注明的范围为准。

### 资产管理入口的一致性

- Skill、MCP、Hook、插件、扩展和状态栏资产共用目录中的状态与操作。状态栏配置也参与顶部搜索和 Agent 筛选，通过同一使用面板管理。
- 原生诊断入口、目录面板、目标选择和实际预览共用启停方向规则；已启用不能重复启用，已停用不能重复停用，状态未知时先核对来源。
- 指定配置的同步操作同样检查内容与目标可用性；内容已经一致或目标无法核对时，不因跳过 Agent 选择页而允许继续写入。
- 内容状态统一为「已同步 / 内容不同 / 内容待核对 / 尚未配置」，与启停状态分别展示。
- 只有完成所选目标的预览后才显示变更卡片及不可执行原因；选择列表不会被当成执行预览。所属插件代管的启停会明确说明实际操作对象和连带影响。
