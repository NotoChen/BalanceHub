# WebDAV 配置同步

入口：**设置 → 网络与数据 → WebDAV 同步**。

本页描述当前仓库源码；安装包是否包含该功能，以对应版本的更新记录为准。

## 连接第一台设备

1. 填写 WebDAV 服务地址、账号和应用密码。服务地址使用网盘提供的 WebDAV 目录地址，用户名和密码分别填写。
2. 设置独立的同步目录，例如 `BalanceHub`。同一组设备填写相同的地址、账号和目录。
3. 设置至少 12 个字符的**同步密码**。它用于本机加密和解密，与网盘的应用密码用途不同；请妥善保存。
4. 填写便于识别的设备名称，例如“办公电脑”。
5. 点击 **测试连接**。应用会实际验证读写、删除临时文件和多设备条件写入能力，结果直接显示在卡片中。
6. 点击 **保存并同步**，在首次同步的差异窗口中核对条目，再点击 **确认同步**。

WebDAV 连接表单需要主动保存；其他应用设置沿用原有的自动保存方式。已保存的应用密码和同步密码不回显，输入框留空会保留原值。更换服务地址或账号时，需要重新填写应用密码。

第二台设备使用同一组连接设置和同步密码，填写自己的设备名称，再核对首次差异。首次连接会合并两端已有配置；同一条目内容不同时，由用户选择保留本机或云端版本。

## 同步哪些内容

| 内容 | 处理方式 |
| --- | --- |
| 中转站名称、地址、协议、备注、账号信息、默认模型、启用状态和排序 | 同步 |
| 手动填写的认证凭据、账号密码、API Key 库和 Key 的静态名称信息 | 加密后同步 |
| 主题、刷新与签到时间、测活模型、间隔和提示词等可移植偏好 | 按字段同步 |
| 共享库 Skill、MCP、Hook 定义 | 同步；Skill 按文件增量传输，Hook 保留所属 Agent 的定义格式 |
| 本机代理、CLI 路径、工作目录、终端、通知渠道、浏览器绑定和登录环境 | 各设备单独保存 |
| 自动刷新、自动签到、自动测活开关 | 各设备单独控制，不因另一台设备开启而自动执行 |
| 额度、可用模型、请求记录、签到记录、测活结果、扫描与会话缓存 | 留在本机，不参与配置同步 |
| 自动续期产生的 Refresh Token、带有效期的 Access Token、NewAPI 短期会话 | 留在本机，避免多设备相互覆盖会话续期结果 |
| Agent 原生配置、插件安装、应用记录及资源执行状态 | 留在本机 |

共享库入口在 **Agent → 共享库**。同步过来的资源会出现在共享库中；需要使用时，再选择 **配置到 Agent**。同步共享定义本身不会安装插件、执行 Hook 或改写 Agent 的原生文件。

## 增量与自动同步

首次同步建立两端的共同版本。后续只上传或下载变化的配置条目与 Skill 文件，未变化的文件复用已有加密对象。共同版本保存在本机，重启后继续使用。

开启 **自动同步** 后：

- 本机配置保存会触发同步，连续保存合并处理。
- 每分钟检查云端变化。本机没有变化时，只检查远端版本，不重新扫描 Agent 资产。
- 不同条目的修改自动合并；同一条目的冲突暂停等待处理。
- 网络失败后逐步延长重试间隔，卡片显示原因与下次重试时间。
- 关闭设置窗口或差异窗口后，任务仍可在顶部任务中心查看。同步进度与中转站刷新进度分别展示。

手动点击 **取消本次同步** 可以取消准备、比较和资源传输。最后提交完整版本与应用本机配置期间会短暂关闭取消入口，界面仍可关闭。单次网络请求有超时，同步任务有总时限。

## 冲突、删除与恢复

冲突窗口以 diff 展示本机和云端内容；Skill 可以逐个文件查看差异，二进制文件显示大小和校验值。每个冲突分别选择 **保留本机** 或 **保留云端** 后确认。

删除也属于配置变更，会传播到其他设备。离线设备不会仅因保留旧副本而自动恢复已删除条目；如果离线期间又编辑了该条目，则需要处理“删除与编辑”的冲突。

从云端删除共享定义，只移除其共享库状态。本机已应用到 Agent 的资源及其历史记录仍然保留。

应用云端变更前会保存一个本机恢复点。需要回退时，展开 **同步范围与恢复 → 恢复同步前的本机配置**：

- 恢复最近一次应用变更之前的中转站、可移植偏好与共享定义。
- 自动同步会暂停；云端版本不会立即回退。
- 已有 Agent 原生配置不会被恢复操作改写。
- 恢复点只有一个，不是长期备份。重要配置仍建议定期使用“数据备份”。

本机写入使用事务记录。任一配置文件保存失败，会回滚本次本机变更；应用意外退出后会在加载配置前处理未完成事务。外部程序又修改了待恢复文件时，会保留文件并报告原因。

## 加密与服务要求

配置条目、Skill 文件和同步清单都在上传前使用 **Argon2id + XChaCha20-Poly1305** 加密。远端文件名是加密内容的 SHA-256；服务仍能看到文件数量、大小和访问时间。同步密码不会作为请求参数发送给 WebDAV 服务，遗失后无法从云端恢复。

连接设置保存在本机独立文件中，不包含在普通配置导出或 WebDAV 同步包里。macOS / Linux 上同步私有文件使用仅当前用户可读写的权限；Windows 沿用当前用户应用数据目录的访问控制。本机拥有相应文件访问权限的程序仍可读取本机配置。

推荐使用 HTTPS。请求复用 BalanceHub 的全局代理设置；地址重定向不会自动跟随，请填写服务的最终 WebDAV 地址。

服务需要支持：

- `MKCOL`、`PROPFIND`、`GET`、`PUT`、`DELETE`。
- 内容变化时可靠更新的强 `ETag`。
- 创建时的 `If-None-Match: *` 和更新时的 `If-Match`。

“测试连接”会连续改写同样大小的临时文件，核对版本变化，并验证过期版本无法覆盖新文件。不满足这些条件的服务会显示具体原因，避免多设备静默覆盖。目录中的 `head.json` 是当前完整版本入口；请勿单独删除或手动编辑它。

资源先上传，最后才提交完整版本。中途断网可能留下尚未被引用的加密对象，但不会替换当前完整版本。远端暂不自动清理历史对象，以免删除其他设备正在使用或上传的内容；需要回收远端空间时，请先保留本机备份，再让所有设备改用新的同步目录。

## 开发验证

仓库提供 `scripts/webdav-test-server.py`，使用真实 WsgiDAV 协议处理并绑定 `127.0.0.1`。测试数据和凭据均为合成数据。正向验证使用内容哈希 ETag；另有故障模式验证默认文件系统 ETag 在快速等长改写时不更新的情况会被拒绝。

在仓库根目录创建临时环境：

```sh
bh_fixture=$(mktemp -d -t balancehub-webdav)
python3 -m venv "$bh_fixture/venv"
"$bh_fixture/venv/bin/pip" install WsgiDAV==4.3.5 cheroot==11.1.2
"$bh_fixture/venv/bin/python" scripts/webdav-test-server.py \
  --root "$bh_fixture/dav" --ready-file "$bh_fixture/server.json" --port 64536
```

保持服务运行，在另一个终端执行专项测试。构建前按 `AGENTS.md` 检查磁盘和构建缓存，低空间例外须有当次用户授权。

```sh
cd src-tauri
CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 \
CARGO_PROFILE_DEV_DEBUG=0 CARGO_PROFILE_TEST_DEBUG=0 \
BALANCEHUB_WEBDAV_TEST_URL=http://127.0.0.1:64536/remote.php/dav/files/fixture/ \
cargo test cloud_sync --lib -- --include-ignored --test-threads=1
```

测试覆盖双设备同步、增量与重启、同项冲突、删除传播、过期预览、加密完整性、丢失响应、存储失败、事务回滚和条件写入。`BALANCEHUB_WEBDAV_FIXTURE_DIR` 仅在需要生成隔离桌面假数据时设置，目标必须位于系统临时目录；不向本机 Agent 写入配置。

本机服务验证不能代表所有网盘实现。商业网盘、NAS 服务及各系统安装包，仍需在对应环境中验证其地址、权限、证书和条件写入行为。
