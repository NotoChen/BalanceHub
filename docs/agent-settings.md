# Agent 可视化配置

进入 **Agent → 总览**，点击卡片底部的 **配置**，进入可视化表单。已有的受支持配置文件也可以直接点击文件名进入。入口优先选择用户配置；尚未创建配置文件时，原生适配器允许创建的位置也可打开，确认保存后才创建文件。

窗口顶部显示实际文件路径。有多个可编辑来源时，可以切换用户、项目、个人本地配置或 Codex Profile。切换来源时按草稿处理流程提示继续编辑或放弃当前修改。

## 编辑方式

**可视化** 和 **原文** 使用同一份草稿。表单修改会转换为原生 TOML、JSON 或 JSONC；切换到原文时先同步待处理的表单修改。原文修改后返回可视化，会重新解析当前草稿。语法或字段值有问题时，窗口显示具体原因并保留草稿。

| 分类         | 常见内容                                                                 |
| ------------ | ------------------------------------------------------------------------ |
| 模型与上下文 | 默认模型、推理强度、上下文窗口、自动压缩阈值或比例、思考预算、输出上限。 |
| 权限与工具   | 文件沙盒、审批方式、工具规则、网络与原生功能开关。                       |
| 规则与目录   | 额外工作目录、规则文本上限。                                             |

分类与字段按所选 Agent、模型和文件范围提供。数值使用与临时 CLI 共用的紧凑滑块及精确输入框；没有固定原生档位的选项允许输入原生值。参数旁的信息按钮展示对应配置键、按草稿解析的值、原文值和读取来源。其他来源覆盖当前文件时，可以在其中核对生效来源。

模型使用可搜索的选择器，列出 **Agent CLI 模型**，同时保留已有配置和手动输入模型 ID 的能力。它与中转站返回的模型列表是两种来源，不能用其中一份推断另一份的权限。

### 模型目录的来源与更新

可选模型目录从所选 CLI 动态读取，并补充当前配置中的模型别名和实际 ID。模型映射使用各 Agent 的原生配置字段，具体目标模型不维护固定名单：

| Agent       | 读取方式                                                                                                                                |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Codex       | 调用原生 `debug models` 更新目录。显式指定 `model_catalog_json` 时只读取该文件；查询失败时可继续显示本地目录。                          |
| Claude Code | 读取官方 Agent SDK 初始化接口返回的模型目录。只发送元数据请求，关闭自定义启动动作，不提交提示词、不保存会话。                           |
| Gemini CLI  | 读取当前安装包导出的模型目录和别名，跟随所选版本变化。此操作不创建 ACP 会话、不初始化 MCP。账号、预览模型权限和网关仍可能影响实际调用。 |
| Grok Build  | 调用原生 `grok models`。尚未登录或未返回目录时显示具体提示，仍可使用已有配置和手动输入。                                                |

打开选择器时先展示已缓存模型，再在后台核对 CLI、安装包和配置文件状态。安装更新或相关文件变化会使缓存失效；正常结果缓存 5 分钟，查询失败后 1 分钟可重试。选择器持续展开时每分钟核对一次，也可点击列表右上角的刷新按钮立即重查。模型查询不参与表单草稿转换，不阻塞配置面板，也不触发资产扫描。

新增或移除模型无需随之发布 BalanceHub；如果 CLI 改变查询协议或安装包的元数据导出格式，则需要适配。目录变化不会清空当前模型选择。WSL 只读取对应环境的目录，不借用宿主 CLI 查询另一份列表。

### 模型别名、映射与用途

在 **模型与上下文** 中编辑。实际模型 ID 决定请求使用的模型，显示名称改变选择器中的文字；保存不会创建代理服务或转换模型协议。目标模型须由对应连接提供支持。

| Agent       | 可视化支持                                                                                                              | 临时 CLI                                                         |
| ----------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| Claude Code | Sonnet、Opus、Haiku、Fable 档位及子 Agent 模型；档位可设置显示名称，已有其他 `ANTHROPIC_DEFAULT_*_MODEL` 配置也会读入。 | 通过本次进程环境覆盖映射，不改写用户文件。                       |
| Gemini CLI  | 新增、修改、移除 `modelConfigs.customAliases` 的模型映射，设置 `extends` 继承其他别名；保留已有生成参数。               | 写入隔离的本次启动设置，合并原生配置。                           |
| Grok Build  | 用户配置中 `[model."别名"]` 的 `model` 与 `name`；保留连接、认证及其他参数。                                            | 可选已有别名；当前 CLI 没有可靠的单次别名配置入口，映射表只读。  |
| Codex       | 默认模型、原生 `/review` 模型、子 Agent 默认模型与推理强度。                                                            | 使用对应的 `-c` 原生参数覆盖。没有添加原生不支持的通用别名字段。 |

映射行直接展示 **别名 → 实际模型**，目标可搜索模型目录或填写 ID。配置来源放在行内的信息按钮中；其他来源覆盖当前文件时显示生效模型。切换主模型不会重写独立的档位映射。

没有明确映射的 Claude 档位显示“Claude 默认 Sonnet”等具体行为，详情说明尚未取得实际型号的原因；子 Agent 显示跟随的主会话模型。Gemini 继承映射展示解析后的模型和实际取值来源，无法解析时说明缺少哪个继承目标；Grok 条目没有 `model` 时明确显示未指定实际模型。配置读取失败单独展示，不作为正常默认映射。

**添加别名** 先填写名称并选定实际模型。Gemini 可进一步选择继承配置，再取消单独设置的实际模型，以使用父别名的模型；循环继承会提示错误并保留草稿。默认模型选择器保留别名本身，选择别名时，其生成参数也继续按原生规则加载。

每行的 **移除映射** 只移除当前文件的模型、显示名称与继承字段，其他来源以及该条目的连接、生成参数仍保留；临时 CLI 中对应 **取消覆盖**。Claude 更换或移除映射目标时，同时清理当前文件中旧目标的描述与能力声明，具体删除内容可以在 diff 中核对。

清空实际模型、移除一行映射、移除整组设置分别计算操作后的取值，其他参数和别名仍参与解析。默认选项与行内说明展示相应结果，避免把整组重置的结果当作单行移除后的结果。

Claude 的默认模型保存到 `model`，同时移除当前文件中更高优先级的 `env.ANTHROPIC_MODEL`，使后续原生 `/model` 选择能够生效。外部环境变量与其他配置来源的优先级不变，实际生效值仍会显示。

Codex 的字段依据：[官方配置参考](https://developers.openai.com/codex/config-file/config-reference)。Gemini 别名及继承依据：[原生 ModelConfigService](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/services/modelConfigService.ts)。Claude 与 Grok 的字段也核对了本地 CC Switch、Magpie 的原生写入实现。

### 参数与默认值

数值控件直接显示实际值，来源可通过参数旁的信息按钮查看。有单独设置时显示 **移除设置**；操作说明同时展示移除后的值与读取来源。下拉的默认项直接显示移除此项后会使用的值，并标明“已配置”“默认值”等状态。当前文件的设置被环境变量或管理配置覆盖时，控件下方显示生效值；已有的工具与目录列表也直接展示。

后端分别返回 **已配置、默认值、未设置、读取失败** 四种状态。已读取的具体值和已知默认值直接展示；文件没有设置、也没有可确认的固定默认数值时显示“未设置”，轨道不标记假定位置。正常的默认行为和未设置状态使用中性样式，只有文件不可读或解析失败才标记读取错误。详情列出配置键、值、来源及必要的行为说明；子 Agent 未单独设置模型时明确说明会跟随父会话或角色。

Codex 功能开关通过本机 CLI 的 `features list` 读取默认值，当前配置中的显式设置优先。查询仅在进程内清除 `features` 覆盖，不改写配置文件、不启动会话；结果按 CLI、配置目录和文件状态缓存，并设置超时。图像生成、浏览器操作、电脑操作等开关直接显示启用或停用；开关启用后，工具的实际可用性仍取决于模型、账号及已安装组件。

不可读或格式错误的配置文件可能覆盖现有值时，不把较低优先级的结果当作已确认的默认值；明确的进程环境覆盖与更高优先级的可读配置仍按实际来源展示。

### 可视化与原文定位

- 当前文件实际写入了对应配置键时，设置旁显示 **原文**，点击后高亮该键；模型映射按每行是否存在对应原文分别提供入口。
- 在原文中将光标放到配置键或值上，点击 **可视化 · 设置名称**，返回相应分类并高亮该设置或映射行。
- 当前文件没有此项时，不显示原文定位入口；默认值、其他来源及配置键仍可通过信息按钮查看。设置生成对应原文后显示定位入口，移除设置后入口随之消失。
- 原文中只有存在对应可视化设置的键和值才显示返回入口。修改原文后，可点击 **解析并定位** 重新解析当前草稿；移动光标不触发额外的后端请求。定位只滚动编辑器或设置列表，不滚动外层弹窗。

Codex 自动压缩默认使用上下文窗口的 **90%**，同时显示 token 数与百分比；明确配置的更小阈值优先。模型资料里的输入可用比例是另一项容量预留，不用它替代压缩比例。Gemini 和 Grok 分别显示原生默认压缩比例 50% 和 85%。Claude 能确定模型时显示官方默认值，部分 1M 模型的默认值约为 967K；账号决定的模型别名未解析时，仍会说明无法读取具体阈值。

Codex 上下文窗口与自动压缩阈值的 token 滑块共用刻度，轨道两端标明范围，可以直接比较数值对应的长度。编辑过程中保留刻度，输入超出范围的数值时同步扩展两条轨道。压缩比例始终以当前上下文窗口计算；拖动范围只用于编辑，不代表服务端容量。

**规则文本上限** 对应 Codex `project_doc_max_bytes`，默认 **32 KiB（32,768 字节）**，限制合并到启动指令的 `AGENTS.md` 等规则文本，0 表示跳过。它与项目文件读取和历史会话检索无关。

**额外工作目录** 用于跨仓库任务，例如同时修改前端与后端。Codex 的额外可写目录仅在“项目内可写”模式下有作用，完全访问模式无需添加；已配置的目录仍可查看和移除。Claude 与 Gemini 按各自原生权限规则增加工作范围，不会自动把整个目录塞进模型上下文。

**移除设置** 会从草稿中删除这一项，再按 Agent 的配置优先级读取其他来源或默认值；确认保存后才写入文件。同一文件中的其他设置仍参与计算。管理策略、环境变量、项目信任和 Profile 选择仍影响实际加载结果；缺少运行时信息时明确说明缺少的依据，不填入推测值。

## 各 Agent 的原生映射

| Agent       | 可视化配置与范围                                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex       | 编辑 `config.toml` 及受支持的独立 Profile。模型、上下文、审批、沙盒、工具和附加可写目录分别保存到其原生键；推理档位与上下文默认值复用本机模型目录。                                                        |
| Claude Code | 编辑用户、项目和个人本地 `settings.json`。模型保存到 `model`，生成参数保存到受支持的 `env` 键，沙盒及权限规则保存到原生章节。项目配置不提供原生会忽略的启动审批模式。                                      |
| Gemini CLI  | 编辑用户和项目 `settings.json`。压缩比例保存到 `model.compressionThreshold`；思考与输出参数使用所选模型主会话的 `modelConfigs.customOverrides`。切换推理级别与思考预算时处理互斥及继承，保留其他生成参数。 |
| Grok Build  | 用户 `config.toml` 支持模型、生成参数、审批、沙盒与工具规则。项目 `config.toml` 的表单只提供原生读取的权限规则；模型默认项在用户配置中编辑。                                                               |

原文模式可以编辑表单未覆盖的字段。修改可视化字段时保留无关配置；未变化的 TOML、JSONC 内容和注释尽量保持原样。认证文件、工作规则文档和其他格式继续使用适合其内容的原文编辑器。

## 可视化覆盖范围

可视化配置目前提供常用运行参数，**没有覆盖所有官方配置项**。工具栏展示当前文件可编辑的字段数量，点击可查看覆盖范围并切换原文。

Codex 还可设置以下参数，临时 CLI 共用同一套字段定义：

| 设置              | 原生键                                                                  |
| ----------------- | ----------------------------------------------------------------------- |
| 回答详细程度      | `model_verbosity`，读取所选模型声明的支持情况与默认值                   |
| 推理摘要          | `model_reasoning_summary`，与推理强度分别设置                           |
| 服务层级          | `service_tier`，按模型目录提供选项，也可填写服务端支持的原生值          |
| 代码审查模型      | `review_model`，未指定时使用当前会话模型                                |
| 子 Agent 默认模型 | `agents.default_subagent_model`                                         |
| 子 Agent 推理强度 | `agents.default_subagent_reasoning_effort`，按所选子 Agent 模型提供档位 |
| 中断消息          | `agents.interrupt_message`，原生默认启用                                |
| 登录 Shell        | `allow_login_shell`，原生默认启用                                       |

子 Agent 并发数根据模型目录中的 `multi_agent_version` 和显式配置解析。Codex V1 默认允许 **6 个子 Agent**；V2 默认 **4 个总线程**，扣除主 Agent 后是 **3 个子 Agent**。面板统一显示子 Agent 数量。存在优先级更高的 `features.multi_agent_v2.max_concurrent_threads_per_session` 时，读取、编辑和保存都会换算主 Agent 占用的一个线程；未配置时显示默认值，打开表单不会把默认值写入文件。

自定义 Agent 角色、复杂环境变量、供应商连接定义、遥测、终端界面与实验性选项等仍由原文编辑；MCP、Skill、Hook、插件等结构化资产使用各自的管理入口。字段支持情况按 Agent、模型、CLI 版本和当前文件范围变化，不能把某个 Agent 的表单当成其他 Agent 的完整配置列表。

## 保存与生效

1. 调整表单或原文，点击 **预览更改**。
2. 在统一 diff 中核对目标文件、删除与新增内容、创建范围及重新加载提示。
3. 点击 **确认保存**，窗口关闭，结果进入后台任务。
4. 按 Agent 的原生规则，在新会话或重新加载后使用新配置。

生成表单草稿不会写文件。真正保存复用原有的文件权限、版本与路径核对；来源被其他程序修改时，需要重新读取并比较草稿。读取、同步草稿和预览均有超时处理，关闭窗口后过期结果不会回写当前界面。

关闭未保存的编辑器后，可再次点击同一文件继续内存中的草稿；退出 App 后不保留。文件可写性由当前用户对文件及所在目录的实际权限决定。

## 与临时 CLI 的关系

两处共用字段定义、原生值解析和滑块控件。Agent 管理保存到选定的原生文件，影响之后读取该文件的会话；[临时 CLI 启动设置](temporary-cli.md) 将选择传给一次启动，点击 **取消覆盖** 后使用 Agent 当前配置。原生没有持久化对应项的启动选项，不出现在原生配置表单中。

打开表单复用已检测的 CLI 路径，不重新扫描安装或资产。CLI 帮助与内置模型资料按可执行文件、真实目标和安装包状态缓存，并定期重查；完整模型列表单独在后台刷新。WSL 使用发行版内的配置路径，不混入宿主系统的环境变量或管理文件；发行版内尚未读取的运行时设置由 Agent 启动时确认。
