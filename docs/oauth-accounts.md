# OAuth 账号与 CPA

本文描述当前仓库源码。发布安装包的功能以对应版本的更新记录为准。

BalanceHub 在中转站面板中集中展示三类卡片：中转站账号、官方 OAuth 账号、CPA 网关。它们共用搜索、排序、刷新和任务入口；每张卡片根据服务实际提供的能力展示信息与操作。

## 添加官方账号

在中转站面板顶部展开 **添加**，选择 **OAuth 账号**，然后选择 Codex、Claude、Gemini CLI 或 Grok。

| 服务 | 授权方式 | 完成位置 |
| --- | --- | --- |
| Codex | 浏览器授权、PKCE | 本机 `localhost:1455/auth/callback` 自动接收结果 |
| Claude | 浏览器授权、PKCE | 本机 `localhost:54545/callback` 自动接收结果；也支持粘贴本次回调 |
| Gemini CLI | Google 浏览器授权、PKCE | 在授权面板里粘贴 Google 授权页面给出的授权码 |
| Grok | 官方设备授权 | 浏览器确认设备码，后台按服务返回的间隔检查结果 |

选择服务后，面板直接切成授权进度：打开授权页面、等待浏览器回调、粘贴授权码、交换令牌和保存账号都在同一个面板里完成，不需要再去任务中心找结果。可以重新打开授权页面、查看当前阶段，或在令牌交换开始前取消。收到授权后即开始保存；若保存失败，可以只重试保存，不必再次登录。关掉面板不会中断授权，任务仍在顶部任务中心继续。

每个服务同一时间保留一个进行中的登录任务。回调端口取决于上游客户端的登记，不能自己挑：`auth.openai.com` 只接受 1455 和 1457（实测 1456 等端口会返回 `invalid_authorize_request`），Claude 则接受任意本机回环端口。因此 Codex 按 1455 → 1457 的顺序在 IPv4 / IPv6 上依次尝试，两个端口都被占用时提示具体端口，改为粘贴回调地址完成授权；Claude 在 54545 被占用时自动改用系统分配的本机端口，浏览器回调仍然自动完成。授权码仅接受当前任务的状态与回调地址。

重新授权会核对实际登录的账号。邮箱相同但工作区、组织或 Google 项目不同的身份不会直接合并；登录了另一个账号时为其添加独立卡片。

## 卡片展示什么

卡片优先展示账号名称、邮箱、套餐和主要额度。点击卡片可展开全部额度窗口、授权状态、导出选项及账号设置。

| 服务 | 可读取的信息 |
| --- | --- |
| Codex | 套餐、主额度窗口、周额度、代码审查窗口、额外额度及服务返回的余额 |
| Claude | 套餐与组织、5 小时和周额度、Sonnet / Opus 等模型窗口、已启用的月度额外用量 |
| Gemini CLI | Google 账号、Code Assist 套餐与项目、按模型返回的剩余额度和重置时间 |
| Grok | 账号等级、周额度、产品额度、月度预算、按量预算与预付余额，以该账号响应为准 |

额度百分比最多保留两位小数。不同服务提供的窗口并不完全相同；没有返回的月限额、余额或到期时间不会填成 0，也不会根据套餐名称推算额度。读取失败会保留上次成功数据并显示原因和数据时间。只返回已用值与上限的窗口会在刷新时补算百分比，因此所有窗口都能按同一把尺子比较；上限缺失或为 0 的窗口仍显示未知。

还没有 Code Assist 项目的 Gemini 账号会在首次读取额度时按 Gemini CLI 的方式开通一次项目（优先免费档位），开通结果写回账号，之后的刷新直接使用该项目。只有完全拿不到项目时才会触发开通，已有项目的账号不受影响。

**额度窗口按已用比例排序，最紧张的排在最前。** 排序在刷新时由后端完成，卡片、详情面板和托盘提示因此都优先显示真正接近上限的窗口，而不是厂商返回顺序里的第一个。卡片列出前三个窗口（与中转站卡片的窗口条数一致），其余收起为数量提示；卡片右上角的套餐标签下，用量进入警示区间后会直接显示该窗口的比例。详情面板按通用额度与模型专属额度分组，并用概览标签标出最紧张窗口、预计耗尽、告急数量、最近重置时间、余额和同步时间。窗口进入 70% 与 90% 时分别转为警示色与告急色。

**额度趋势来自 BalanceHub 自己的采样。** 厂商接口只返回当前值，因此每次刷新会把各窗口的已用比例追加到本地历史，按窗口 ID 续写，最多保留 24 个采样点；比例没有变化或本次没有返回比例时不新增点，旧版本数据会在下一次刷新时开始积累。卡片和详情面板在每个窗口右侧用迷你折线展示这段变化，悬停可看到采样次数、最低与最高比例以及累计变化。

**预计耗尽是对本地采样的估算。** 当同一窗口至少有两个间隔 10 分钟以上的采样、并且在上升时，BalanceHub 会按这段速度推算达到 100% 的时间；只有该时间早于窗口自己的重置时间才提示「约 N 后耗尽」，避免把会被重置化解的增速当成风险。这是本机观察结果，不是服务端承诺，界面会同时说明以服务端额度为准。

访问令牌的到期时间按剩余时间显示；距离到期不足 24 小时时以警示色标记，提示续期可能已经暂停。

**可用模型来自账号接口动态读取。** Gemini 从额度响应中的模型读取，其他服务使用对应模型接口。卡片直接列出前几个可用模型，点击可查看完整列表。未同步和成功取得空列表是不同状态；刷新失败也不会清空已有列表。

账号详情的 **授权原文** 展示 BalanceHub 实际保存的 `balancehub-oauth` 内容，可直接查看或修改访问令牌、刷新令牌与身份字段。保存前会再次核对账号 ID 和用户 ID，不接受把另一账号的授权粘贴到当前卡片；保存成功后清除待确认的续期状态，并更新卡片。手工替换令牌不会影响远端 CPA 或其他应用中已有的副本。

OAuth 卡片不参与每日签到、站点 Key 管理或 API Key 测活。普通中转站卡片继续保留这些对应协议的能力。

## 续期与交接

新登录的账号由当前设备负责续期。导入其他应用的授权时，默认只读取该授权，不接管续期；确认原应用已暂停使用后，可以在账号详情开启 **本机自动续期**。

刷新令牌可能在每次使用后轮换。BalanceHub 按账号串行执行续期，并在发出请求前记录待确认状态；遇到中断或不明确的结果时暂停续期，要求重新授权，避免反复使用已经消耗的令牌。重新授权拿到的新令牌本身就是一次新的授权，保存时会替换卡片并清除中断留下的待确认状态，因此面板上的 **重新授权** 就是恢复入口。

导出时可以选择暂停本机续期。直接发送授权到 CPA 时会先暂停，即使网络断开也保持暂停，方便先核对远端是否已收到文件。交接后的账号仍可展示已有信息，访问令牌到期后需要重新授权或重新导入。

关闭账号卡片只会停止 BalanceHub 对该卡片的自动操作。CPA 授权列表中的开关会改变远端凭据的启用状态，两者作用不同。

## 授权文件互通

在顶部 **导入授权文件** 中选择 JSON 文件。导入预览只展示服务、身份、套餐、到期时间与已有账号匹配情况，原始令牌留在后端。可以批量选择，并决定是否替换已经存在的账号、是否由本机接管续期。

一次最多读取 64 个文件、总计 8 MiB，单文件最多 4 MiB。预览有效期为 10 分钟，完成或关闭后丢弃；已有账号在预览后发生变更时需要重新核对。

下表表示已按目标项目源码实现的同类授权文件互通，不代表不同厂商的登录授权可以相互转换：

| 格式 / 应用 | Codex | Claude | Gemini CLI | Grok |
| --- | --- | --- | --- | --- |
| BalanceHub 授权文件 | 支持 | 支持 | 支持 | 支持 |
| CPA | 支持 | 支持 | 当前 Google 入口使用其他 OAuth 客户端 | 支持 `xai` |
| CC Switch 独立账号库 | 支持 | 无相同独立账号文件入口 | 无相同独立账号文件入口 | 支持 |
| NewAPI 渠道授权 | 支持 Codex 渠道 | 无相同 OAuth 文件入口 | 无相同 OAuth 文件入口 | 无相同 OAuth 文件入口 |
| Sub2API 账号数据 | 支持 | 支持 | 支持 `code_assist` | 支持 |
| Magpie 内建文件导入 | 支持 | 支持 | 由插件或其他 Google 授权流程管理 | 由插件管理 |
| 原生 CLI 文件 | 支持 | 支持文件格式 | 支持 | 支持 |

目标格式不适用或授权字段不完整时，导出面板会显示具体原因。例如，原生 Codex 文件需要 ID Token 与工作区，Claude Code 原生文件需要到期时间和授权范围，Magpie 导入需要刷新令牌。自定义 OAuth 客户端的授权仅提供 BalanceHub 格式，保留原客户端信息。

### 常见文件及入口

| 目标 | 输出内容 / 使用方式 |
| --- | --- |
| BalanceHub | `format: balancehub-oauth`、`version: 1` 与 `accounts` 数组，在本应用导入授权文件 |
| CPA | 包含 `type`、`access_token`、`refresh_token` 等字段的 JSON，在管理面板上传或直接发送到已连接的 CPA |
| CC Switch | `codex_oauth_auth.json` / `xai_oauth_auth.json` 账号库格式；退出目标应用后合并 `accounts` 条目，保留原有账号 |
| NewAPI | Codex 授权 JSON，在管理员的 Codex 渠道中作为渠道密钥使用 |
| Sub2API | `sub2api-data` 账号导入包；导入后在 Sub2API 中设置分组、代理和并发 |
| Magpie | 使用对应账号的“导入授权文件”入口；Claude 保留账号与组织字段 |
| Codex CLI | `CODEX_HOME/auth.json`，其中 `tokens` 保存授权 |
| Claude Code | `.credentials.json` 的 `claudeAiOauth`；使用 macOS 钥匙串的安装应通过原生登录接入 |
| Gemini CLI | `.gemini/oauth_creds.json`，保留 Code Assist 授权 |
| Grok CLI | `.grok/auth.json` 中对应 issuer / client 的条目，保留文件内其他条目 |

导出使用系统文件选择器，只创建新文件，不覆盖已有文件。Unix 文件权限设为 `0600`。这些文件包含可使用的授权，应保存在自己的可信设备上。

OAuth 卡片也能直接启动临时 CLI，只把该卡片自己的授权交给对应厂商的 Agent：Claude Code 使用 `CLAUDE_CODE_OAUTH_TOKEN`，Codex、Gemini CLI 和 Grok 在启动目录内建立各自的临时配置目录。启动不会改动本机已登录的原生授权，也不会写入刷新令牌。

### 卡片操作

OAuth 卡片与中转站、API Key、CPA 网关卡片共用同一排底栏，卡型只决定哪些动作有数据：

- 信息位先标出凭据类型；**续期失败** 显示失败原因，**续期待确认** 表示上次续期没有明确结果并已暂停自动续期，两者都占这个位置并提示需要重新授权。没有续期问题时，该位置显示正在使用这张卡片授权的 Agent（图标 + 名称，多绑定时带 `+N`）。
- 动作按钮按固定顺序排列：启动临时 CLI（仅该厂商支持的 Agent）、刷新额度与模型、切换默认授权、重新授权、编辑、启停、删除。重新授权只在续期失败或待确认时出现并换成警示色，点击即重新执行该厂商的登录流程并在授权面板里显示进度。
- 切换默认授权把这份授权写成 Agent 的原生登录，只列出与卡片厂商匹配的 Agent；该 Agent 正在使用本卡时按钮显示 Agent 图标并高亮，否则显示切换箭头。
- 二级动作收进复制 / 数据 / 站点 / 导出四组菜单，菜单名按卡片自己的称呼读（中转站、账号、网关），分组数量与顺序不随卡型改变；可用模型与 API Key 管理在站点菜单里，导出到其他应用在导出菜单里。
- 点击卡片或底栏的编辑按钮打开账号面板，授权原文编辑、导出授权文件与发送到 CPA 在面板里执行。

导出与发送在账号面板里同一时间只执行一个，执行期间按钮禁用，失败或取消后恢复。

### 切换到本机 Agent 授权

OAuth 卡片可以通过底栏的切换按钮把该账号写成对应 Agent 的原生授权，覆盖该 Agent 当前的登录。这个切换不需要先备份：之后再选另一张卡片（中转站卡片或另一张 OAuth 卡片）会直接覆盖，Agent 重启后按新的凭据运行。

写入的是各 Agent 官方使用的授权文件与字段：

| Agent | 写入 | 同时清理 |
| --- | --- | --- |
| Codex | `auth.json` 的 ChatGPT 登录 | `config.toml` 中的 `model_provider`、`openai_base_url` |
| Claude Code | `.credentials.json` 的 `claudeAiOauth` | `settings.json` 中 `env` 下的中转地址与令牌（`ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_API_KEY` 会优先于存储的登录） |
| Gemini CLI | `oauth_creds.json` | `security.auth.selectedType` 设为 `oauth-personal`；`.env` 中的 `GEMINI_API_KEY`、`GOOGLE_API_KEY`、`GOOGLE_GEMINI_BASE_URL` |
| Grok | `auth.json` 中对应 issuer / client 的条目 | `xai::api_key` 记录、`endpoints.models_base_url` |

清理中转字段是为了让厂商登录成为唯一可用的凭据；文件内其他 Agent、其他账号的条目原样保留。

切换前后的注意事项：

- Codex 只有在 `cli_auth_credentials_store` 未设置或为 `file` 时才从 `auth.json` 读取登录；其他取值会拒绝切换并提示改回 `file`。
- Claude Code 开启了 `CLAUDE_CODE_USE_BEDROCK`、`CLAUDE_CODE_USE_VERTEX` 或 `CLAUDE_CODE_USE_FOUNDRY` 时，云服务商优先于存储的登录，切换会被拒绝并提示先关闭。
- macOS 上 Claude Code 可能把登录保存在钥匙串而不是 `.credentials.json`，此时文件切换不会改变已经在用的登录。需要该机原生登录时请用 `/login`；只想用这张卡片的授权时用临时 CLI。
- 切换后 BalanceHub 仍会为该卡片续期；该 Agent 当前绑定的是别的账号时不会续期这份授权，切回来前可能需要重新授权。
- 这份授权同时被 Agent 自己使用和续期。Agent 轮换刷新令牌后，BalanceHub 保存的旧令牌可能失效，需要重新授权再用回这张卡片。

Gemini CLI、Antigravity、AI Studio 使用的 OAuth 客户端与授权范围不同；Grok OAuth 与旧的浏览器 SSO Cookie 也不同。不能通过改 `type` 字段把它们互转。

## 添加 CPA 网关

在顶部 **添加 → CPA 网关** 中配置：

1. **网关地址**：CPA 服务根地址，可包含部署前缀。
2. **管理密钥**：用于读取授权列表，以及执行明确选择的导入和启停操作。
3. **API Key**：可选，用于读取该调用 Key 的模型和原有临时 CLI 能力。

管理密钥与调用 Key 分开保存。面板底部显示网关上报的自身版本和所使用的管理接口，例如 `CPA v0.9.1 · v8 管理接口`；版本由网关在每个管理响应中附带，不额外发起请求。网关卡片和中转站卡片用同一块额度区块：主数字是可用授权数与总数（如 `2 / 3`），下面是成功率条，模型区照常；逐时间桶的请求分布、服务分布和按授权汇总的请求次数都在详情面板里。详情提供账号搜索、多选导入、远端启停，以及每个授权的模型、成功/失败次数、优先级、权重、独立重试次数、备注、最近续期与排除模型。展开账号后可编辑调度字段、查看远端授权文件、查看最近请求分布、请求 CPA 续期、重置冷却或移除该授权。工具栏的 **全部续期** 让 CPA 一次刷新所有授权；**诊断** 菜单汇集 **插件**（网关上报的插件清单及启用、配置、注册与额度能力）、**请求日志**（网关日志文件尾部）、**调用用量**（网关配置里内联 API Key 凭证的成功/失败次数，按上游提供方分组，密钥默认打码）、**错误日志**（网关主机上的请求错误日志，按需读取原文）和 **检查网关更新**（由网关向 GitHub 查询最新发布版本）。

详情里的 **调度与重试** 折叠区管理整个网关的调度方式：路由策略可选轮询、加权轮询或优先填满，并与请求重试次数、最多重试账号数、重试间隔和出站代理一起编辑。同一折叠区还列出网关的 **路由** 开关（是否强制请求携带授权文件配置的模型前缀、是否让 AI Studio 授权为 WebSocket 请求提供鉴权）、**配额耗尽** 行为（额度用尽时是否换用同一账号的另一个项目、是否回退到预览模型）和 **日志与用量** 开关（是否记录调试日志、是否为每个请求单独记录日志、是否记录用量统计、日志总量上限与错误日志保留文件数）。修改先留在本地草稿，点 **保存调度设置** 才写回网关；清空数字输入表示保留网关当前值，清空出站代理表示直连。这一组设置属于网关而非单个授权，因此不会出现在每个账号行里。折叠区底部的 **编辑完整配置** 打开网关自己的 `config.yaml` 原文，用来修改上述字段之外的配置项：保存时网关会先校验，校验不通过就保留原配置并显示网关给出的原因；v8 网关还会核对读取时的版本标记，其他会话改过配置时拒绝保存。保存成功后编辑器重新读取网关规范化后的文件，配置里可能含有密钥，内容只在本机与网关之间传输。

**客户端密钥** 折叠区列出网关上可直接调用模型的 Key，与连接用的管理密钥互不相同。密钥默认只显示前后几位，可逐条显示或复制；输入自有密钥后点 **添加**，留空则点 **生成密钥** 由本机生成一条 `sk-` 密钥，生成的密钥会保持可见，直到关闭该折叠区。删除密钥前会提示：使用它的客户端会立即无法调用网关，网关上的上游授权不受影响。网关按整份列表替换密钥，写入时会带上读取时的配置版本标记，其他会话改过密钥时提示刷新后重试。

**模型排除与别名** 折叠区管理网关级的模型规则，键是通道（`claude`、`codex`、`gemini`、`xai`、`kimi`、`aistudio`、`vertex` 等）。折叠区按通道显示当前的规则数量，两张表分别保存：模型排除列出每个通道不暴露给下游的模型 ID，模型别名把上游模型改名为下游看到的名称（`fork: true` 时同时保留原名，另可选 `display-name` 与 `force-mapping`）。打开模型排除后先选通道，面板向网关读取该通道真实的模型目录并逐项列出：勾选即写入一条精确规则，目录外的模型和通配符写在下方文本里，每行一条。规则大小写不敏感，只有 `*` 是通配符，其余字符按字面量匹配（`gpt-4.1` 里的 `.` 不是通配符）；某个模型若同时被通配符命中，取消勾选后仍会标注「通配符 X 也会排除」，避免误以为点击没有生效。切换通道不会丢掉已改的内容，保存时把整张表一次写回，清空某个通道的规则会把该通道从表中移除。模型别名仍按 JSON 原文编辑。网关会规范化写入内容（通道名转小写、丢弃空列表），保存后面板重新读取并显示网关确认的结果。

**添加账号** 让网关自己发起授权：BalanceHub 只展示授权链接和设备码，令牌由网关保存，本机不保留这份账号。授权服务列表来自网关内置通道和已加载的插件，插件提供的入口会标注插件名。浏览器能直接完成回调时对话框会自行结束；设备码流程会给出需要在服务商页面输入的代码。网关与本机不在同一台机器时，浏览器最后会停在一个本机打不开的回调地址，把地址栏里的完整链接粘贴到 **回调地址或授权码** 再提交，由网关完成换取。关闭对话框或切换卡片会取消网关上的待授权会话，避免一直占着回调端口；v0 网关使用它自己的取消路由，两种管理接口都能立即结束会话。

CPA 的 `active`、`pending`、`refreshing`、`error`、`disabled` 等状态分别展示为可用、待验证、续期中、连接异常和已停用。运行时凭据没有对应文件时，不提供文件导入操作。

处于冷却或退避的授权会显示 **冷却中** 标记，展开后给出 CPA 报告的冷却原因、预计恢复时间或退避等级。**重置冷却** 会清除这份授权在 CPA 侧的冷却与退避状态；只有额度确实恢复时才应执行，否则请求会很快再次失败。重置需要 CPA 提供该授权的索引。

网关报告某份授权可以查询额度时，展开后会出现 **额度** 区。点 **读取额度** 由网关上的插件向上游查询一次，返回套餐、余额或总量等汇总数字，以及按窗口划分的剩余比例与重置时间；已用比例按 `1 - 剩余` 绘制。这一步只读取，不改动授权、不触发续期，也不会写入本机。上游拒绝查询、插件不提供额度或返回结构无法识别时，原因只显示在该区，不影响卡片其他操作。

连接优先使用 v8 管理接口，仅在路由不存在时尝试 v0；认证失败不会换接口重试。v8 的配置树按版本标记写入，读取设置时得到的标记会随保存一并提交，其他会话已改动配置时提示刷新后重试，不覆盖对方的修改。请求次数由授权列表中的成功/失败计数汇总得出。管理接口没有累计 Token 总量，v8 的用量队列属于消费接口，因此面板不展示 Token 合计，也不读取该队列。请求日志只在网关开启写入日志文件时可用：面板先读开关，关闭时直接给出 **开启日志写入** 入口，而不是把空日志当作读取失败；开启或关闭会重新加载网关配置，可在同一窗口切换。打开后按游标只读新增行，**跟随** 每 5 秒续读一次；网关轮转或截断日志文件时会返回新的末尾，面板据此替换缓冲区而不是把两段不相接的日志拼在一起。筛选框按包含关系过滤当前缓冲区，跟随续读的新行同样参与筛选，不影响已读取的内容；级别筛选按日志级别收窄。每一行按网关的日志格式拆出时间、请求 ID、级别、来源与正文，带请求 ID 的行可以直接点开该请求自己的日志文件——CPA 在开启「单独记录请求日志」时为每次请求各写一份，内容只属于那一次请求，请求文件不存在时面板会说明可能是该开关未开或日志已被清理。**清理日志** 会先说明影响：网关清空正在写入的日志文件并删除已轮转的文件，日志无法恢复，之后继续写入新日志；已轮转文件的数量会在清理后回报。插件清单显示已发现、已配置、已注册、额度能力与授权入口；每个插件可单独启停，并可编辑网关保存的 JSON 配置。插件写入只有 v0 管理路由提供，v8 配置树没有对应入口，因此这一步固定使用 v0。插件面板的 **插件商店** 读取网关配置的商店来源，列出可安装插件及已安装版本与可更新项，可按名称、作者或标签筛选；安装由网关从来源下载并启用，面板只提交所选条目与其来源、版本。安装前会说明插件是第三方代码、将在网关上运行；来源读取失败只显示在对应来源上，其他来源的条目照常可用。已安装的插件可 **移除**：网关会同时删除插件文件与 `plugins.configs.<id>`，插件自己保存的凭据随之删除；仍在运行的插件需要重启网关后才能移除。

将本机 OAuth 账号发送到 CPA 时使用新的文件名，并保留远端已有文件。远端状态与调度字段修改、续期请求、冷却重置和移除操作都会先重新读取授权列表，用文件名和账号索引再次核对目标；网关没有明确确认成功时会要求刷新核对。

远端授权文件由 CPA 以附件形式提供，BalanceHub 只读取原文用于核对，不提供覆盖保存：替换整份文件会中断该账号在 CPA 侧的续期。需要修改调度信息时使用字段编辑；需要更换令牌时先在 BalanceHub 重新授权，再重新发送到 CPA。

## WebDAV 与备份

WebDAV 同步 OAuth 卡片的身份、名称、备注、偏好和排序，**不传输访问令牌、刷新令牌、ID Token、客户端密钥或续期归属**。另一台电脑会看到账号信息，可按需重新授权或显式导入授权文件。

同一身份在当前设备已经登录时，云端修改卡片信息会保留本机会话；云端换成另一身份时不会沿用旧令牌。完整应用备份仍按原有备份功能处理，应与单独授权导出一样妥善保管。
