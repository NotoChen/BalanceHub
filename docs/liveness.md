# 测活配置

测活用于观察某个中转站在 Agent CLI 场景下是否可用。当前内置 Codex CLI、Claude Code、Gemini CLI 和 Grok Build；测活只通过所选本机 CLI 执行真实请求，不提供直接 HTTP 调用。它不是普通余额刷新，也不会替代请求日志。

## 全局与单站配置

可以在 **应用设置 → 自动化 → 自动测活** 中开启测活，也可以在中转站的 **运行设置** 中单独覆盖配置。

展示规则是：

- 中转站启用测活时，卡片展示测活线条。
- 中转站未启用测活时，不展示测活线条。
- 测活周期可按站点稳定性和额度成本自行配置。

## CLI 路径

BalanceHub 会自动查找已注册的独立 Agent CLI。在 **Agent** 视角中，点击对应卡片的版本号进入 **版本与路径**，可以检查本机已有安装、选择启动路径，或按需执行深度扫描。

尚未安装时，点击 **安装说明** 查看官方指南，自行安装后回到 App 刷新。已有安装的升级会先预览，确认后沿用原渠道和目录在后台执行。具体步骤见 [Agent 工作台](agent-workbench.html)。

如果换电脑后提示找不到 CLI，优先检查：

- CLI 是否已安装。
- BalanceHub 是否采用了预期的安装路径；机器上有多个版本时，安装完成不会自动切换原有选择。
- 终端里是否能执行对应的版本命令，例如 `codex --version`、`claude --version`、`gemini --version` 或 `grok --version`。
- 手动路径是否指向真实可执行文件。
- Windows 下路径是否包含 `.cmd` 或 `.exe`。

## 测活提示词

在自动测活设置中选择固定提示词、随机抽取模板或依次使用模板。当前策略对应的正文直接显示，模板每行一条。

**变量设置** 中分别填写变量名和候选值，每行一个候选值；在模板中使用 `{变量名}` 引用，数字变量的范围可单独设置。**预览 10 条** 只展示生成示例，不发送测活请求；修改正文或变量后旧预览会清除。**恢复推荐** 需要确认，替换提示词策略、模板和变量素材。

## 模型与凭据

测活使用当前中转站配置的模型、Base URL 和认证信息，并在隔离目录内构造所选 Agent 的运行环境。不要依赖本机已有的 CLI 默认配置，否则可能测到错误的账号。

如果测活记录显示“无效令牌”，优先检查当前中转站使用的是 Cookie、访问令牌还是 API Key，以及测活命令里对应的认证参数。
